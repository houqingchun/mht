# UI/UX与交互实现规范

## 1. 设计原则

1. 先工作、后分析：心理老师首页优先显示待复核、逾期跟进和复测任务。
2. 先事实、后判断：量表结果、学校风险、人工复核和跟进记录分区展示。
3. 最小必要披露：德育领导看到进展和聚合，不默认看到原始答案及访谈正文。
4. 学生安心作答：语言非诊断化、无成绩感、支持保存退出和主动求助。
5. 每个高敏感动作都可解释：查看前说明用途，完成后留痕。

## 2. 视觉基线

- 主色：深海军蓝、低饱和蓝、青绿色；风险色仅用于风险状态，不大面积使用红色。
- 管理端正文约16px，表格约14px，辅助信息12-13px。
- 学生题干建议20-27px，选项按钮至少18px。
- 页面背景使用浅灰蓝，卡片白色，边框和阴影克制。
- 重点状态同时使用文字、颜色和图标，不依赖颜色单独传达。
- 适配宽屏管理端、平板和手机；表格在窄屏横向滚动。

## 4. 登录交互

- 登录页先选择角色，动态显示“学号/手机号/管理员账号”字段。
- 密码默认隐藏，可显示/隐藏。
- 错误信息使用非攻击性文案：“账号、角色或密码不正确”。
- 登录成功进入对应角色首页，不允许通过URL访问未授权页面。
- 顶部显示当前账号、角色和退出按钮。
- 管理员显示“账号管理”，其他角色点击时不可执行重置。
- 原型可保留本地演示账号，但正式系统不提供前端角色自由切换。

## 5. 心理老师工作台

顶部四个可点击指标：待复核、逾期跟进、未来30天复测、本学期完成率。点击后进入对应列表并保留筛选条件。

重点学生列表必须支持：

- 姓名/学号/年级/班级搜索
- 风险等级、当前阶段、逾期状态筛选
- 单选、多选、全选当前筛选结果
- 批量分配负责人
- 批量导出
- 高度关注受控导出
- 进入学生档案

## 6. 学生档案

使用标签页分离：

- 测评概览
- 跟进记录
- 家庭回访
- 复测趋势
- 访问审计

重点题必须先出现二次确认弹窗，再显示具体回答。人工复核表单必须要求“复核结果、已确认事实、下次跟进日期”。

## 7. 学生答题

- 每次只显示一道题。
- “是/否”使用大面积可点击选项，键盘可操作。
- 自动保存答案和当前题号。
- 支持定位未答题目。
- 提交前显示已答/未答数量，并要求二次确认。
- 提交后锁定答案，学生端不展示分数、维度、风险标签或诊断描述。
- 始终提供“我想找人聊聊”入口。

## 8. 导入/导出

导入统一采用：选择文件 → 解析 → 校验预览 → 错误报告 → 确认写入。禁止选择文件后直接写库。

导出统一采用：选择范围 → 选择用途 → 选择脱敏级别/字段 → 二次确认 → 下载 → 写审计。

## 9. 可用性验收

- 所有按钮有明确动作反馈。
- 保存成功、失败、无权限和空数据均有可理解提示。
- 删除或关闭操作必须二次确认。
- 弹窗支持Esc关闭、点击遮罩关闭和键盘焦点管理。
- 首屏不依赖外部CDN，不因脚本加载失败出现空白。
