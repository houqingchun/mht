# 心晴中学生心理测评与关怀平台

## Vibe Coding 输入包 V1.0

本目录是基于 `mht-care-prototype-v2.1.html` 整理的开发输入基线。目标是让 Coding AI 先理解产品边界、角色、数据、接口和验收条件，再分阶段实现代码。

## 文件说明

| 文件 | 用途 |
|---|---|
| `01_project_context.md` | 项目目标、范围、技术边界与角色概览 |
| `02_business_rules.md` | MHT评分、风险提示、重点学生和持续关怀规则 |
| `03_auth_rbac_security.md` | 登录、密码、RBAC、数据范围、审计和隐私要求 |
| `04_uiux_interaction_spec.md` | 页面、交互、视觉、响应式和可用性规范 |
| `05_data_model_contract.md` | 核心实体、字段、状态和数据关系 |
| `06_api_contract.md` | REST API、请求响应和错误处理约定 |
| `07_acceptance_tests.md` | 自动化测试和人工验收标准 |
| `08_vibe_coding_plan.md` | 分阶段开发顺序、AI行为约束和交付物 |

## 推荐输入顺序

1. 先读取 `01`、`02`、`03`，确认业务和安全边界。
2. 再读取 `04`、`05`、`06`，生成页面、数据库和接口设计。
3. 用 `07` 生成测试用例并冻结验收口径。
4. 按 `08` 分阶段编码，不允许一次性生成整个系统。

## 已冻结的角色

- 学生
- 心理老师
- 德育领导
- 系统管理员

不得恢复“班主任”或“心理负责人”角色。

## 重要产品边界

本系统是心理健康筛查与学校关怀管理系统，不是医疗诊断系统。任何页面、接口、提示词和AI输出都不得表达“患有某种心理疾病”等诊断结论。

## 给 Coding AI 的总指令

你必须把本目录作为项目基线。未定义的业务规则不得自行发明；冲突标记为 `RULE_CONFLICT`，缺少决策标记为 `TODO_BUSINESS_CONFIRMATION`。原始答案、量表计算结果、学校风险事件、人工判断和跟进记录必须是独立事实，不能相互覆盖。
