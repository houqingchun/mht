## 1. 产品定位与边界

### 1.1 定位

面向中学的**心理健康筛查与学校关怀管理系统**。系统帮助学校发现需要关注的学生、组织人工
工作、查看聚合趋势；**不替代心理老师的专业判断**。

业务闭环（8 环，全部已实现）：

```
测评任务 → 学生答题 → 自动评分 → 风险提示 → 人工复核 → 跟进 → 家庭回访 → 复测 → 关闭/重开
```

### 1.2 红线（不得违反的表述约束）

| 编号 | 约束 | 落地位置 |
|---|---|---|
| R1 | 任何页面文案、接口、AI 输出**不得表达「患有某种心理疾病」**等诊断结论 | 全站文案；个案页风险卡写明「提示不等同于诊断结论」 |
| R2 | 学生端**不展示**分数、风险标签、重点题与诊断性描述 | `StudentHomePage.vue`、`StudentHistoryPage.vue`、`StudentAssessmentPage.vue` |
| R3 | 提示语统一用「需要关注 / 重点关注 / 建议重测」，不用疾病名 | `labels.ts` `LEVEL_LABELS`、`VALIDITY_LABELS` |
| R4 | 角色固定为四类，**不得恢复「班主任」「心理负责人」** | `models/enums.py` `RoleCode` |

### 1.3 四层事实模型（互不覆盖）

| 层 | 表 | 语义 |
|---|---|---|
| 原始答题事实 | `assessment_session`、`assessment_answer` | 学生答了什么，写一次 |
| 量表计算事实 | `assessment_result`、`dimension_result` | 按哪个规则版本算出了什么，含 `rule_version` |
| 学校管理事实 | `risk_event`、`assessment_task`、`assessment_target`、`student_care_case` | 学校组织了什么 |
| 专业工作事实 | `manual_review`、`follow_up_record`、`family_contact_record`、`retest_plan` | 老师做了什么 |

**两条不变量：人工复核不得修改原始答卷；关闭档案不得删除历史记录。**

## 2. 角色、权限与数据范围

### 2.1 四类角色

| 角色码 | 中文 | 登录账号形态 | 登录后落地页 |
|---|---|---|---|
| `student` | 学生 | 学号（`STUDENT_NO`） | `/student/home` |
| `counselor` | 心理老师 | 手机号（`MOBILE`，`^1\d{10}$`） | `/counselor/workbench` |
| `leader` | 德育领导 | 手机号（`MOBILE`） | `/leader/overview` |
| `admin` | 系统管理员 | 管理员账号（`ADMIN_USERNAME`，`^[A-Za-z0-9._-]{3,32}$`） | `/admin/system` |

登录匹配 **账号 + 账号类型 + 角色三者同时成立**（`auth_service.authenticate`），所以角色与
账号创建后**不可修改**。

### 2.2 能力矩阵

五类能力按角色配置，存 `role_permission` 表，实现在 `security/permissions.py`。
**表空 / 缺记录 / 查询抛 `SQLAlchemyError` 时一律回退 `CAPABILITY_DEFAULTS`，绝不 fail-open。**

| 能力 | counselor | leader | admin | student |
|---|---|---|---|---|
| `AGGREGATE_STATS` 聚合统计 | SCOPED | SCHOOL | NONE | NONE |
| `STUDENT_PSYCH_DETAIL` 学生心理详情 | SCOPED | SUMMARY | NONE | NONE |
| `KEY_QUESTIONS` 重点题/原始答卷 | GRANTED_WITH_AUDIT | NONE | NONE | NONE |
| `ORG_ACCOUNT` 组织与账号 | READ_BASIC | READ_SUMMARY | MANAGE | OWN |
| `CONTROLLED_EXPORT` 受控导出 | PSYCH_SUMMARY | PROGRESS_SUMMARY | BASE_ONLY | NONE |

**描述性等级不可互换**：暴露个案明细的端点必须显式传 `allow={SCOPED}`，否则 admin 的
`BASE_ONLY`、leader 的 `SUMMARY` 会被静默提升（`api/v1/care.py:42`）。

### 2.3 每项能力的合法等级定义域

配置界面的下拉框**只列该能力的合法值**（`CAPABILITY_LEVELS`，`permissions.py:76`）：

| 能力 | 可选等级（从紧到松） |
|---|---|
| 聚合统计 | 无 → 授权范围 → 学校范围 |
| 学生心理详情 | 无 → 仅摘要 → 授权范围 |
| 重点题/原始答卷 | 无 → 单独授权+审计 |
| 组织与账号 | 无 → 本人 → 查看汇总 → 查看必要信息 → 管理 |
| 受控导出 | 无 → 仅基础数据 → 管理进展摘要 → 授权心理摘要 |

每格下方有一句「选了会怎样」的说明（`LEVEL_DESCRIPTIONS`）。同一串等级名在不同能力下
含义不同，说明按能力分别撰写。

### 2.4 数据范围（与能力互补的第二层）

`security/data_scope.py` 回答「**这个**学生归不归**这个**用户管」。**两个入口缺一不可**：

| 入口 | 用在 | 语义 |
|---|---|---|
| `ensure_student_in_scope(db, user, student_id)` | 客户端传来的 ID | 取到之后校验，否则档案 ID 本身成为越权凭据 |
| `student_scope_predicate(db, user)` | 列表 / 聚合查询 | 加进 WHERE，把结果集收缩到用户范围 |

- 范围四级：`SCHOOL` / `GRADE` / `CLASS` / `STUDENT`（`ScopeType`）。
- **谓词绝不返回 `None`**：读不到 scope 行时返回恒假谓词，不 fail-open。
- 拒绝时**不写审计**——给被拒的读取记一条「查看重点题」会让访问轨迹反向撒谎。
- `student_in_scope` 建立在谓词之上，所以「列表里出现的」与「个案接口接受的」不可能各说各话。

**范围口径在界面上写明**：「全部学生」页头写「范围：全校 / 你负责的班级 …」，依据是
`/auth/me` 的 `scopes[]`；取不到时整句不出现，不猜。

### 2.5 账号从哪来（两条路径）

| 角色 | 从哪来 | 理由 |
|---|---|---|
| 学生 | **名册导入**（组织学生 → 学生信息导入） | 身份属性是学号/年级/班级/年龄，只有名册知道 |
| 心理老师 / 德育领导 / 系统管理员 | **账号与权限 → 新建账号** | 身份属性是职责与所辖范围，与名册无关 |

- `POST /admin/accounts` 收到 `role_code=student` 时返回**指路的 422**，不是接受。
- **数据范围必填**（`scopes` 是 `min_length=1`），且**先解析范围再落账号行**；界面上拉不到
  选项就拒绝打开弹层（空的范围下拉框会把「必填」变成死路）；范围为空的行显示琥珀色
  「**未配置 · 看不到任何学生**」，不是与别的行一样的 `—`。
- `STUDENT` 级范围在这个入口被拒（422）。
- **停用 ≠ 删除**：没有删除接口（`audit_logs` / `manual_review` / `follow_up_record` 都指着
  `user_account`）。停用**立即生效**——`get_current_user` 每个请求都查一次 `active`。
  停用时顺手清 `failed_attempts` / `locked_until`。**管理员不能停用自己**。
- 审计用四个动作码：`新建账号` / `更新账号` / `停用账号` / `启用账号`；**密码一律不进 detail**。

### 2.6 登录、锁定与密码

| 规则 | 值 / 行为 |
|---|---|
| 密码错误累计 | 5 次（`XLP_PASSWORD_LOCK_THRESHOLD`） |
| 锁定时长 | 30 分钟（`XLP_PASSWORD_LOCK_MINUTES`），错误码 `ACCOUNT_LOCKED` 423 |
| 登录失败提示 | 用户不存在 / 已停用 / 密码错误**共用同一句**，不泄露账号是否存在 |
| Token | JWT，有效期 120 分钟（`XLP_ACCESS_TOKEN_EXPIRE_MINUTES`） |
| 首次登录 | `must_change_password=True` 时前端强制弹出修改密码弹窗，不可取消 |
| 忘记密码出路 | 安装目录的 `重置管理员密码.bat`（不需要重装、不需要 mysql 客户端），重设即解锁 |
| 失败分支的区分 | `fetch` 抛 `TypeError` → 「无法连接服务器」；`SyntaxError` → 「服务端返回了无法解析的响应」；否则用服务端原文 |

四种登录失败在屏幕上**长得不一样**是有意为之：此前一律报「账号、角色或密码不正确」，
于是「后端没起来」与「密码打错了」无法区分。

**校验规则**（`student_import_service`）：

- 必填：学号 / 姓名 / 年级 / 班级。
- **班级编号规则**：`701 / 801 / 901`，首位 `7/8/9` 分别是初一/初二/初三，并与「年级」列
  交叉校验；对不上按行报错（`班级 704 属于初一，与年级 初二 不一致`）。年级只认
  `初一 / 初二 / 初三` 三个名字。
- 年龄：整数 3–100，容忍尾随「岁」，拒绝全角数字；老模板末列仍叫「出生日期」时逐行挡下
  并说明列已改名。
- 性别：`MALE / FEMALE / 男 / 女`，**不认数字**（与测评导入相反）。
- 学号重复：**文件内重复是错误**（没有覆盖语义）；**名册上已存在是冲突**，可覆盖或放弃。
- 选填列（性别 / 年龄）文件里空着就跳过，**不写 NULL**。
- **覆盖是就地改，不删了重建**，且只改姓名的六列（姓名/年级/班级/性别/年龄/展示名 +
  账号展示名）；**学号不改**（它是冲突判据）、**状态不改**。

## 5. 功能清单 · 量表与评分规则

### 5.1 版本生命周期

`DRAFT` 草稿 → `PUBLISHED` 已发布 → `ARCHIVED` 已归档。

- **草稿不生效**：不参与评分，新建任务也不会选中它。
- **发布归系统管理员**（`POST /scales/versions/{id}/publish`），同时把同量器上一个已发布版本
  转为 `ARCHIVED`（保留，不删除）。
- **导入开放给管理员 + 心理老师**。

### 5.2 接口

| 功能 | 接口 | 权限 | 落点 |
|---|---|---|---|
| 版本列表 | `GET /scales/versions` | ADMIN + COUNSELOR | `scales.py:27` |
| 题库导入预览 | `POST /scales/import/preview` | ADMIN + COUNSELOR | `scales.py:88` |
| 创建草稿版本 | `POST /scales/drafts` | ADMIN + COUNSELOR | `scales.py:99` |
| 读取评分规则 | `GET /scales/versions/{id}/rule` | ADMIN | `scales.py:139` |
| 保存评分规则 | `PUT /scales/versions/{id}/rule` | ADMIN | `scales.py:150` |
| 恢复默认规则 | `POST /scales/versions/{id}/rule/reset` | ADMIN | `scales.py:182` |
| 发布版本 | `POST /scales/versions/{id}/publish` | ADMIN | `scales.py:212` |

### 5.3 题库导入校验

- 格式：`.json`（必须是数组）或 CSV，`utf-8-sig` 解码。
- 列别名：`question_no/题号/no`、`question_text/题目文本/text`、`dimension_code/维度`、
  `is_validity_question/是否效度题`、`is_key_question/是否重点题`。
- **逐行**：题号在 1–100；文件内不重复；题干非空；非效度题的维度码必须是八个之一。
- **全局**：共 100 题；题号恰好 1–100；效度题集合 == `{82,84,…,100}`；重点题集合 == `{85,97}`。
- 通过后再跑一遍 `ScaleEngine.validate_questions` 作第二道网。
- 提交只创建 `DRAFT` 版本 + 100 道题 + 一条 `ACTIVE` 规则。

### 5.4 评分规则版本化

- **规则标识统一由 `rule_version_for(code, version)` 生成**（`MHT` + `MHT-1.1.0` →
  `MHT-RULE-1.1.0`）；标识里**不得出现生命周期词**。
- 改**已发布**版本的规则 → 旧规则行转 `RETIRED`，生成**新版本**（`1.0.0 → 1.0.1`）；
  已有结果不受影响。
- 改**草稿**版本的规则 → 就地修改。
- 保存前校验：分段非空、`min <= max`、按 `min` 排序后**无重叠**、效度题/重点题必须在量表
  实际题号范围内、`validity_retest_threshold >= 1`。
- `assessment_result.rule_version` 因此永远能回答「这条结果当时按什么标准判定」。

**界面**：`ScalePage.vue`（`/admin/scale`「量表题库」）+ `ScaleRulePanel.vue`。

> ⚠️ **`ScalePage.vue` 的「发布」按钮当前不可用**，见 §10 缺口 D1。

**系统管理员整块退出这个功能面**（读与写都不含 ADMIN）。理由：测评任务是学校业务，
管理员只关注系统级配置。

### 6.2 发放规则

- 目标行发给全校 `status == "ACTIVE"` 的学生 **∩ 创建者的数据范围**。
- `task_no = TASK-{YYYYMMDDHHMMSS}-{序号}`；`scope_type = SCHOOL`。
- **目标行是建任务那一刻拍下的快照**，`PATCH` 不会补发。见 §10 缺口 D2。

### 6.3 任务状态是**现算的**

`task_service.effective_task_status` 由**已被记下来的事实**推出，优先级：

| 顺序 | 事实 | 状态 |
|---|---|---|
| 1 | 库里那一列不是 `ACTIVE` | 以库里为准（人写的 `DRAFT`/`PAUSED`/`CLOSED` 不可被推导盖过） |
| 2 | 还没到 `start_at` | `NOT_STARTED` 未开始 |
| 3 | 过了 `end_at` | `CLOSED` 已结束，**不管还有没有人没答** |
| 4 | 目标行全部完成（且总数 > 0） | `CLOSED` 已结束 |
| 5 | 其余 | `ACTIVE` 进行中 |

- **两个消费者共用它**：任务列表与「学生能不能新开一张卷子」。
- **口径是整场任务，不是读者的范围**（状态与 `name` 一样是任务自身的属性）。
- **「已结束」不等于「把人踢出卷子」**：那道门排在「已有会话直接返回」**之后**，窗口关闭那
  一刻答到一半的学生不会被踢出去。
- 延期的出路是 `PATCH` 改 `end_at`。

### 6.4 完成明细

每名学生一行：学号 / 姓名 / 年级 / 班级 / 性别 / 年龄 / 状态（未开始·进行中·已完成）/
**这一场的**关注等级与总分 / 分配时间 / 完成时间 / 用时。

- **口径是「这一场」，不是「每人最近一场」**——一名学生落在两个批次里时两边各显示各的分。
- 未交卷的行**照样出**（外连接），等级显示「未测评」。
- 明细屏的搜索框也匹配**状态的中文**，所以输入「未开始」即可筛出没参加的人。
- 表格只渲染前 200 条，会写明「仅显示前 200 条」并指向「导出CSV」；**筛选先于截断**，
  搜「未开始」不会因截断漏人。

**界面**：`TasksPage.vue`（`/counselor/tasks`、`/leader/tasks`）。心理老师有「新建/编辑」，
德育领导只读。

### 7.2 关键规则

- **会话创建**要求存在目标行（否则 403），且任务状态为 `ACTIVE`（否则 **404**）。
  已存在的会话**直接返回**；`source == "IMPORTED"` 的会话返回 409
  `SESSION_LOCKED`（外部答卷不能在本系统里作答）。
- **单题保存**：题号必须 1–100；会话已交卷 → 409；答案只认 `YES`/`NO`。
  **重答会更新行但不重打 `answered_at`**，所以用时不会被「改第 1 题」压缩。
- **拉题目不下发** `dimension_code` 与重点题标记——学生不得从接口推断某题在测什么。
- **交卷幂等（两层）**：
  1. 已存在 `AssessmentResult` → 直接返回既有结果（与请求头无关），重试不会重复计分；
  2. 存量与传入的 `Idempotency-Key` 都存在且不同 → 409 `IDEMPOTENCY_CONFLICT`。
- **完整性由引擎判定**（对照规则版本的 `question_count`），此处不重复计数。
- **用时** = 交卷时刻 − **最早一题的作答时刻**（不是 `started_at`，避免把离开页面的时间算进去）。
- 交卷后写审计 `提交测评答卷`。

### 7.3 答题页的四条特殊约定

`StudentAssessmentPage.vue` 是唯一一个学生长时间停留、且答错代价由他自己承担的页面：

- **题数只定义一次**（来自 `getSessionQuestions`），进度、导航、「定位未答」、预计时长全部
  从它派生，不写死 100。
- **题干拉不到就没有答题页**——只剩一条错误与「重试」。此前会退化成占位卡而作答与提交照旧
  可用，学生能交出一份「每道题都不知道在问什么」的答卷。
- **光标按会话存**（`xlp_assessment_cursor:<sessionId>`），答案以服务端为准，本地不留副本。
  共用电脑上遗留的全局键会被删除，不迁移。
- 回到哪一题：本地光标 → 服务端 `current_question_no` → 最后一题。

## 8. 功能清单 · 评分引擎与风险提示

### 8.1 引擎（纯函数，不碰数据库）

`scale_engine/engine.py`：输入题目配置 + 答案 + 规则配置，输出 `ScaleCalculation`。

| 输出 | 规则 |
|---|---|
| `validity_score` | 效度题中答「是」的题数（默认效度题 `{82,84,86,88,90,92,94,96,98,100}`） |
| `validity_status` | `validity_score >= 阈值`（默认 7）→ `RETEST_RECOMMENDED`，否则 `VALID` |
| `total_score` | **只统计内容题**（排除 10 道效度题），答「是」计 1 |
| `total_level` | 默认 `GENERAL_RANGE 0–55` / `NEEDS_ATTENTION 56–64` / `KEY_ATTENTION 65–90` |
| `dimension_results` | 八个维度各自的得分与等级（默认 `LOW 0–3` / `MEDIUM 4–7` / `HIGH 8–15`）+ 中文解释 |
| `risk_events` | 见下 |

维度编码为**英文**（`LEARNING_ANXIETY` 等八个），默认题号映射：
学习焦虑 1–15、人际焦虑 16–25、孤独倾向 26–35、自责倾向 36–45、过敏倾向 46–55、
身体症状 56–70、恐怖倾向 71–80、冲动倾向 {81,83,85,87,89,91,93,95,97,99}。

### 8.2 风险事件的触发条件（**只有一条**）

**重点题（默认 85 / 97）答「是」** → 写一行 `risk_event`：
`risk_type=MANUAL_REVIEW_REQUIRED`、`risk_level=HIGH_SENSITIVITY`、
`trigger_rule=KEY_QUESTION_{n}_YES`，并开出/复用关怀档案。

> **总分落入「重点关注」区间本身不产生风险事件。** `engine.py:263` 只从重点题生成
> `risk_events`；`maybe_raise_risk_events` 是 `RiskEvent` 全库**唯一**的写入方
> （`assessment_service.py:494`）。这一条直接影响「什么样的学生会进关怀队列」，
> 详见 §10 缺口 D3。

系统内作答与外部导入**共用这一条链路**（`submit_session` 与 `commit_assessment_import`
都调 `maybe_raise_risk_events`），两条路径不可能各判各的。

### 8.3 档案的开启与复用

`open_or_reuse_care_case`：先找该学生**非 `CLOSED`** 的最新档案，找不到才新建
（`status=PENDING_REVIEW`）。「同一时间只有一条在办」由**写入侧**保证，不是数据库约束
（迁移 0012 删掉了那个 `UniqueConstraint`）。

在办的新档案。

### 11.3 MHT 测评记录导入（外部普查结果）

| 功能 | 接口 | 权限 | 落点 |
|---|---|---|---|
| 模板下载 | `GET /assessment-import/template` | ADMIN + COUNSELOR | `assessment_import.py:39` |
| 预览 | `POST /assessment-import/preview` | ADMIN + COUNSELOR | `assessment_import.py:50` |
| 提交 | `POST /assessment-import/commit` | ADMIN + COUNSELOR | `assessment_import.py:72` |

**文件格式**：**只收 `.csv`**。解码依次尝试 `utf-8-sig` → `gbk`（Windows/WPS 另存为 CSV 的
编码）。其它扩展名整份拒绝并**说清该怎么办**（「请先将文件另存为 .csv 后重试」）。

**列约定**：姓名 / 性别 / 年龄 / 年级 / 班级 / 所用时间 + 100 个题目列。题目列按正则
`^\s*(\d{1,3})\s*(?:[.、．)。:：]|$)` 识别（支持 `1.题干`、`1、…`、裸数字）。
**题面不逐字校验**——同一道题会有措辞变体，逐字比对会把学校唯一的那份文件全拦下来。

**取值约定**：性别 `2=男 / 1=女`；答案 `1=是 / 0=否`；年级 `1/2/3` = 初一/初二/初三；
班级 `4` → `704`（两位补年级前缀，三位必须 `7xx/8xx/9xx` 且首位与年级一致）。

**学生定位** `locate_student`：姓名 + 年级 + 班级定位到一名学生；候选先按操作者数据范围
过滤；同名同学先用性别、再用精确年龄、最后用 **±1 岁容差**消歧（名册年龄是上次导入时
冻结的数）。

**判重按月**：同一学生、同一自然月只能有一次导入（窗口 = `tested_on` 所在月）。不同月份是
两场不同的测评、两个批次任务。

**冲突（需要人拍板，不是错误）**：

| 码 | 含义 | 覆盖的后果 |
|---|---|---|
| `AGE_MISMATCH` | 文件年龄 ≠ 名册年龄 | 写回名册年龄并记审计「更新学生年龄」 |
| `DUPLICATE` | 本月已有一次导入 | 就地改写那一场 |

处置是**文件级**的一次选择（`overwrite` / `skip`）；未选而文件里有冲突 → 422，
且**在任何写入之前**拦下。

**提交写入**：批次任务（复用同月最新的一条，没有则建 `IMPORT-YYYYMM-{N}`，`end_at=None`）
→ 每生一条 `status=COMPLETED` 的目标行 → 会话（新建或就地改写）→ 100 条答案
→ **与系统内作答同一条链路**：`calculate_session` → 持久化结果 → `maybe_raise_risk_events`
→ 定会话状态。

- **就地改写只收回 `PENDING` 且无人复核的风险事件**——老师写过的复核是工作记录。
- 全部行被跳过时**不建任务**（空任务会永远显示「进行中」）。
- 风险事件与档案的时间用**导入时刻**，不是测评日期。

**界面**：`DataCenterPage.vue`（`/counselor/data`，「数据中心」）——心理老师的导入台。
含题库导入、测评记录导入、近期数据任务（来自审计日志）、高度关注导出。

## 12. 功能清单 · 导出

| 导出 | 接口 | 门槛 | 落点 |
|---|---|---|---|
| 关注档案摘要 | `POST /care-cases/export` | `CONTROLLED_EXPORT ∈ {PSYCH_SUMMARY, PROGRESS_SUMMARY}` | `audit.py:139` |
| 高度关注摘要 | `POST /care-cases/high-risk/export` | 同上 | `audit.py:172` |
| 单个学生摘要 | `POST /care-cases/{student_id}/export` | 同上 + `ensure_student_in_scope` | `audit.py:202` |
| 任务完成明细 | `GET /assessment-tasks/{id}/completion/export` | COUNSELOR + LEADER | `tasks.py:104` |

### 12.1 遮蔽规则

- 遮蔽模式 `mask_student_name(name)` = 姓 + 「同学」，**读取时现算**。
  `student.masked_name` **不是隐私控制**——三条写入路径写的都是真名，它只是展示名。
- 遮蔽导出表头：`学号, 学生, 年级, 班级, 关注等级, 用时(秒), 来源, 档案阶段, 负责人`；
  解除遮蔽**才**加 `性别, 年龄`（身份列与姓名同进同出）。
- **解除姓名遮蔽同样要 `STUDENT_PSYCH_DETAIL: {SCOPED}`**，否则 `MASK_FORBIDDEN` 403。
  受控导出不得成为读心理详情的旁路。
- `high_risk_only` 与 `student_ids` 不能同时给（422）。
- 数值列（用时、总分）没有记录就**留空**——写 `—` 会让整列被表格软件当成文本。
  等级列没有结果则写「未测评」，不留白。

### 12.2 审计

每次导出都要求非空 `purpose`，并写审计行，**detail 里记遮蔽模式**
（`{scope} · 实名|姓名遮蔽`）——同样的 action、同样的 purpose，遮蔽与实名两条行本来长得
一模一样。

### 12.3 「高度关注」与「重点关注」是同一个东西

等级只有一套中文：`KEY_ATTENTION` 一律叫「重点关注」。但那个导出功能在按钮、弹层标题、
后端错误文案与**审计动作码**（`导出高度关注摘要`）里都叫「高度关注」。

**不改名的理由**：审计动作码是已落库的历史，用户在审计页按眼睛看到的名字搜索；改界面不改
审计码会落进「把看不懂换成了搜不到」。所以处置是**在用户将要动手的那一处写出等号**——
三个导出入口都有一行「「高度关注」就是关注等级里的**重点关注**（同一档）」。

## 16. 部署与运维

两条路并存，各有各的场景。

### 16.1 Windows 一键安装包（推荐给学校那台机器）

产物 `dist/心晴部署包_V<版本>.zip`（约 11MB）→ 拷到目标机 → 解压 → 双击 `一键安装.bat`。
目标机上**不需要** Docker，需要 **Python 3.11 x64** 与 **MySQL 8.0**。

安装时有三个正交的维度：

| 维度 | 取值 | 说明 |
|---|---|---|
| **用法** `usage` | `single` 单机 / `lan` 局域网 | 单机绑 `127.0.0.1`、装到 `%LOCALAPPDATA%`、不提权、不建计划任务；局域网绑 `0.0.0.0`、装到 `C:\xinliceping`、要 UAC、建计划任务与防火墙规则 |
| **数据库由谁准备** | `installer`（默认）/ `prepared` / `schema_prepared` | 三种取值只差一件事：这个库里，哪几样归操作员 |
| **首次安装 / 升级** | — | 升级沿用上次的用法（不重问）、不动管理员密码、只补 `.env` 的坏行 |

- **单机用法起一个可见的控制台窗口**，关掉窗口就是停服务；注销也会停。
- **崩溃重试在 `run_server.py` 里**（Task Scheduler 的 `RestartOnFailure` 只管「根本起不来」），
  数据库连不上时指数退避封顶 30s。
- `.env` 是 CWD 相对的，所以启动器进门就 `chdir` 到仓库根。
- 升级**不用人先去停服务**，安装程序自己会停（不停就装不上：正在跑的进程锁着 venv 里的 DLL）。

运维脚本（装完在安装根目录）：`启动服务.bat`、`停止服务.bat`、`重启服务.bat`、
`查看状态.bat`、`查看日志.bat`、`备份数据.bat`、`重置管理员密码.bat`、`卸载.bat`。

**卸载不删数据**：只删计划任务、防火墙规则与程序文件；数据库里的东西一行不碰，并在界面上
明说。

**一键安装装不完时的出路**：`deploy/windows/手工启动后端.bat` / `手工启动前端.bat`
（前端那一路必须是 `serve_frontend.py`——`API_BASE = '/api/v1'` 是相对路径，前端必须与 API 同源）。

### 16.2 Docker Compose

`mysql` + `backend` + `frontend`（nginx 反代）三个容器。

## 17. 非功能需求

### 17.1 统一响应封装

所有接口返回 `{ success, data, request_id, error }`。前端统一取 `body.data`，错误取
`body.error.message` 抛 `Error`。

**「服务端答了话」与「一个字都没收到」分得开**：`fetch` 失败抛 `TypeError`（后端没起来、
网断了），响应体不是 JSON 抛 `SyntaxError`（网关错误页），其余情况 `err.message` 就是服务端
发回来的那句话。

### 17.2 状态词汇契约（三个面）

后端返回的状态/等级/维度编码必须能被 `frontend/src/services/labels.ts` 映射。

| 面 | 谁在守 | 漏了会怎样 |
|---|---|---|
| 后端发出的编码 `labels.ts` 认不认 | `test_status_vocabulary.py` | 界面显示原始编码 |
| 视图有没有**调用**标签函数 | `e2e/vocabulary.spec.ts` | 界面显示原始编码 |
| 服务端生成的导出文件认不认 | `test_export_labels_match_frontend.py` | 导出的 CSV 里是 `MALE`、`FOLLOWING` |

`services/export_labels.py` 是 `labels.ts` 那五张表的镜像，测试把那份 TypeScript 当数据源读
进来逐字比对。**改中文要同时改两边。**

**第四面：枚举列的排序。** `Column.order` 必须显式声明为 `labels.ts` 的 `*_ORDER`
（由映射表的键序生成），否则「关注等级」会按字母序排成「一般观察 → 重点关注 → 需要关注」。

### 17.3 呈现约定

| 约定 | 规则 |
|---|---|
| `None` ≠ `0` | `0` 是「一个都没有」，`None` 是「这几个人算出来不足为凭」 |
| 数值列 | 没有记录就**留空**（`—` 会让整列被当成文本） |
| 等级列 | 没有结果出「未测评」，不留白 |
| **凡是截断都要自己说出来** | 全站五处上限，每处都有一句「还有多少没显示」加一条出路 |
| 指标卡与它点进去的列表必须同源 | 新增卡片时先问「它点进去是什么，那个列表按什么筛」 |

### 17.4 失败、空态与竞态

- **空态是一句关于数据的话**，不能在一次读取失败时落下。错误分支要**排在**空表行之前。
- **一次失败的读取不许留下上一次的答案**：取数之前先清空。
- **竞态：只有最后一次请求的答案算数**（`services/latest-request.ts`），已接三处
  （审计页搜索、评分规则面板、任务完成明细）。

### 17.5 无障碍契约

弹窗焦点陷阱 + `aria-modal` + 焦点归还；面板在打开状态下被卸载也要解锁滚动；`aria-sort`
只给可排序列；可排序表头可聚焦、Enter/Space 可点；全站 `:focus-visible`；
`.metric[role="button"]` 才有手型光标；toast 容器的 `role="status"` + `aria-live="polite"`；
登录页角色页签 `aria-pressed`；表单控件有 `label`；`meta.title` → `document.title`。

### 17.6 安全

- **后端鉴权是最终权限来源，前端隐藏不是安全措施。**
- 系统管理员不能移除自身的「组织与账号」权限，也不能停用自己（自锁防护）。
- 受控导出不得成为读心理详情的旁路；心理详情同样不得成为读组织名册的旁路。
- 一次失败的读取**不写审计**（拒绝时写会让访问轨迹反向撒谎）。

## 18. 已知边界与尚未实现

> 把这一章与前 17 章分开，是为了让「已实现」这四个字可信。

| 编号 | 缺口 | 影响 |
|---|---|---|
| **D1** | **`ScalePage.vue` 的「发布」按钮点了没反应** | `ConfirmDialog` 已导入（`:7`）、`showPublish`/`askPublish`/`confirmPublish` 都定义了、按钮绑 `@click="askPublish(row)"`（`:248`），但**模板里没有任何 `<ConfirmDialog>`**，`showPublish` 无人读取。结果是**新导入的题库永远发布不了**（只能走 API），而草稿不参与评分、任务也不会选中它。e2e 只断言已发布行的按钮数为 0，从未点过草稿行的「发布」，所以这条路径没有测试覆盖。 |
| **D2** | **任务目标行是建任务那一刻的快照** | `PATCH /assessment-tasks/{id}` 只改名称与日期，不补发目标行；全仓库 `AssessmentTarget(` 只有建任务、种子、测评导入三个写入方。**建完任务之后再补导名册（转学生、后补录）的学生不会出现在完成明细里**，屏幕上看起来跟「名册上没这个人」一样。 |
| **D3** | **总分等级不触发风险事件** | 风险事件与关怀档案只由「重点题 85/97 答是」触发（`engine.py:263`）。一名学生总分落在「重点关注」区间但没命中重点题时，**不会**产生待办、**不会**开关怀档案，因此在心理老师能到达的三个入口（工作台、重点学生、学生档案）上都**不存在**。这直接影响「什么样的学生进关怀队列」。 |
| **D4** | **关怀档案没有状态机守卫** | 复核 / 跟进 / 家庭回访 / 复测 / 关闭 / 重开六个动作可从任意状态触发，各自动改写档案状态与负责人。已关闭的档案可以再被直接「跟进」而不经过「重新打开」。 |
| **D5** | **审计页的「角色」列按编码排序** | 那一列是服务端排序，`ORDER BY actor_role` 排的是编码，`Column.order` 到不了那里。要修得在 SQL 里加 `CASE` 表达式。同一页的「对象」列直接渲染 `EXPORT` / `RISK_EVENT` 等裸编码（修它要三件事一起做：先加 `resource_type` 筛选器、再改中文、最后改搜索提示）。 |
| **D6** | **前端没有路由守卫** | `main.ts` 无 `beforeEach`，越权访问表现为「被弹回登录页」而不是 403 页面。 |
| **D7** | **审计的 `detail` 没有出口** | `GET /audit-logs` 不发 `detail`，审计页也不渲染。所以遮蔽模式、导入的 `created/updated/skipped` 与 `resolution`、年龄覆盖的旧新值——**全部写进了库，没有任何接口或界面能读出来**。 |
| **D8** | **单校写死** | 学生导入、测评导入、建任务三条链路都硬编码 `School.code == "QH"`。多校部署要先改这里。管理员自身也受 scope 约束（seed 给的是 `SCHOOL/青禾`）。 |
| **D9** | **小范围聚合的反推风险未完全关闭** | 比率与均值有 `MIN_COHORT_FOR_AGGREGATE` 护栏，但**计数仍然全量下发**；`dimension_distribution` 的 `high_rate` 与 `average_score` 未加小样本护栏。把范围切到 `STUDENT` 级之前要重新想。 |
| **D10** | **`StudentHomePage.vue` 的题数写死 100** | 答题页已改成从题库派生，首页的「N / 100 题」与进度条仍是字面量。 |
| **D11** | **任务没有人工结束/重开按钮** | `DRAFT` / `PAUSED` / `CLOSED` 三个码有词条与词汇表，**没有任何写入方**；状态全靠现算。 |
| **D12** | **部署侧若干未做** | 没有 TLS（局域网用法只给局域网用）；没有「单机 → 局域网」的在线切换（只能卸载重装）；局域网用法的「备份数据.bat」对普通用户失效；备份不自动上传；没有自动放行杀毒软件。 |
| **D13** | **`docker-compose.yml` 与文档的密码不一致** | compose 里 MySQL 是 `root/root`，而 README 与 `core/config.py` 默认值是 `root/password`，按 README 起容器再本地起后端会连不上。 |
| **D14** | **审计页的搜索提示与后端行为对不上** | 提示写「搜索行为、对象或用途」，而服务端 `q` 不匹配 `purpose`。 |

### 18.1 待业务确认的口径（实现侧已按某一条落地）

| 项 | 当前实现 |
|---|---|

## 附录 A · 枚举与中文词汇

| 枚举 | 值与中文 |
|---|---|
| 关注等级 | `KEY_ATTENTION` 重点关注 → `NEEDS_ATTENTION` 需要关注 → `GENERAL_RANGE` 一般观察 |
| 档案阶段 | `PENDING_REVIEW` 待复核 → `FOLLOWING` 跟进中 → `OBSERVING` 观察中 → `CLOSED` 已关闭 |
| 任务状态 | `DRAFT` 草稿 → `NOT_STARTED` 未开始 → `ACTIVE` 进行中 → `PAUSED` 已暂停 → `CLOSED` 已结束 |
| 量表状态 | `DRAFT` 草稿 → `PUBLISHED` 已发布 → `ARCHIVED` 已归档 |
| 目标行状态 | `NOT_STARTED` 未开始 / `IN_PROGRESS` 进行中 / `COMPLETED` 已完成 |
| 来源 | `IN_SYSTEM` 系统内作答 / `IMPORTED` 外部导入 |
| 效度状态 | `VALID` / `RETEST_RECOMMENDED` 建议重测 |
| 维度等级 | `LOW` / `MEDIUM` / `HIGH` |
| 八个维度 | 学习焦虑、人际焦虑、孤独倾向、自责倾向、过敏倾向、身体症状、恐怖倾向、冲动倾向 |
| 学生状态 | `ACTIVE` 在读 / 其他 已离校 |

`*_ORDER`（枚举列的排序依据，由映射表的键序生成）：等级**从重到轻**、档案阶段与任务状态
**按流程先后**、来源**先自家后外部**。空值与认不出的码排在最后，两个方向都是。
