## 1. 修订结论

V1.1既有基线（V1.1.1评审版继续沿用）包括：

1. 角色固定为学生、心理老师、德育领导、系统管理员，不恢复班主任或心理负责人。
2. 学生用学号登录，心理老师和德育领导用手机号登录，系统管理员使用`admin`账号。
3. 初始密码为`123456`；生产环境必须哈希存储、首次登录强制改密、失败锁定，管理员可以重置密码。
4. 原始答题、量表计算、学校筛查信号、人工判断和跟进记录分别保存，互不覆盖。
5. 重点题人工复核、普通筛查信号和效度复测建议分为三类业务信号。
6. 答案在提交前允许修改，提交后不可修改；评分结果绑定量表版本和规则版本。
7. 跟进、家庭回访、复测必须关联具体关怀档案，同时保留学生维度历史查询能力。
8. 外部测评导入必须保存导入批次、原始文件摘要、实际测评时间和逐行处理结果。
9. 所有业务时间统一按UTC存储，接口使用带时区的ISO 8601格式，界面按学校时区展示。
10. 同一学生只能有一条未关闭关怀档案，历史关闭档案允许多条。

## 2. 产品定位与边界

### 2.1 产品目标

系统形成如下闭环：

```text
测评任务 → 学生答题 → 自动评分 → 筛查信号 → 人工复核 → 跟进 → 家庭回访 → 复测 → 关闭/重新打开
```

系统用于：

- 组织学校心理健康筛查；
- 计算MHT量表结果；
- 识别需要进一步了解的学生；
- 提醒授权心理老师进行人工复核；
- 管理持续跟进、家庭回访和复测；
- 提供学校、年级、班级聚合统计。

系统不用于：

- 精神疾病诊断；
- 自动判断自杀风险或心理疾病；
- 替代心理老师、医生或其他专业人员；
- 向学生、德育领导或未经授权人员展示原始敏感答卷。

### 2.2 文案红线

页面、API、导出、AI辅助摘要均不得输出：

- “患有某种心理疾病”；
- “已经确诊”；
- “一定存在自杀倾向”；
- “治疗完成”或“已经治愈”。

允许使用：

- 一般观察；
- 需要关注；
- 重点关注；
- 命中重点关注题目，建议心理老师及时人工复核；
- 建议复测；
- 得分较上次上升/下降。

## 4. 四层事实模型

### 4.1 原始答题事实

表：`assessment_session`、`assessment_answer`、`assessment_import_batch`、`assessment_import_row`、`assessment_external_result`。

- 学生提交前可以修改答案；
- 提交后答案锁定；
- 人工复核不得修改答案；
- 外部导入修改必须通过导入批次并保留处理记录。

### 4.2 量表计算事实

表：`assessment_result`、`dimension_result`。

保存：

- 量表版本；
- 规则版本；
- 效度分；
- 总分；
- 8个维度分数和等级；
- 计算时间；
- 计算状态。

### 4.3 学校筛查治理事实

表：`assessment_task`、`assessment_task_scope`、`assessment_target`、`risk_event`、`student_care_case`、`student_roster_import_batch`、`student_roster_import_row`。

记录学校何时、因为何种筛查信号、对学生创建了什么工作事项。

### 4.4 专业工作事实

表：`manual_review`、`follow_up_record`、`family_contact_record`、`retest_plan`、`care_case_event`。

记录心理老师实际确认的事实和处理过程，不覆盖量表结果。

## 5. MHT评分规则

### 5.1 题目和维度

MHT共100题，答案为“是/否”，是=1分，否=0分。

| 维度 | 题号 |
|---|---|
| 学习焦虑 | 1-15 |
| 对人焦虑 | 16-25 |
| 孤独倾向 | 26-35 |
| 自责倾向 | 36-45 |
| 过敏倾向 | 46-55 |
| 身体症状 | 56-70 |
| 恐怖倾向 | 71-80 |
| 冲动倾向 | 81、83、85、87、89、91、93、95、97、99 |

正式编码统一为：

```text
LEARNING_ANXIETY
SOCIAL_ANXIETY
LONELINESS
SELF_BLAME
SENSITIVITY
PHYSICAL_SYMPTOMS
FEAR
IMPULSIVITY
```

### 5.2 效度量表

效度题为82、84、86、88、90、92、94、96、98、100。

```text
validity_score = 10道效度题中回答“是”的数量
```

建议规则：

| 条件 | validity_status |
|---|---|
| 效度分低于7 | `VALID` |
| 效度分大于等于7 | `RETEST_RECOMMENDED` |

答案不完整、规则错误或计算失败属于`calculation_status`，不与效度状态混合。

### 5.3 总分

总分不包括10道效度题，满分90分。

| 总分 | total_level |
|---:|---|
| 0-55 | `GENERAL_RANGE` 一般观察 |
| 56-64 | `NEEDS_ATTENTION` 需要关注 |
| 65-90 | `KEY_ATTENTION` 重点关注 |

### 5.4 维度等级

| 分数 | 等级 |
|---:|---|
| 0-3 | `LOW` |
| 4-7 | `MEDIUM` |
| 8及以上 | `HIGH` |

所有规则保存`rule_version`，历史结果不可被新规则自动重算覆盖。

## 6. 三类业务信号

### 6.1 普通筛查信号

触发条件：

- 总分达到`KEY_ATTENTION`；或
- 维度达到`HIGH`；或
- 其他已配置的筛查规则。

处理方式：

- 创建`SCREENING_SIGNAL`；
- 进入心理老师“关注候选”列表；
- 不自动表达为疾病或诊断；
- 不自动展示重点题；
- 是否建立持续关怀档案由心理老师人工决定。

### 6.2 重点题人工复核事件

第85题或第97题回答“是”时：

- 创建`MANUAL_REVIEW_REQUIRED`；
- `requires_manual_review=true`；
- 自动创建或复用一条未关闭关怀档案；
- 提醒授权心理老师及时人工复核；
- 查看具体回答必须填写查看原因并记录审计。
- 风险事件必须保存触发规则版本；第85/97题只能归为人工复核信号，不能映射为普通维度筛查信号。

### 6.3 效度复测建议

效度分大于等于7时：

- 创建`RETEST_RECOMMENDED`；
- 不自动创建高敏感风险事件；
- 可生成复测建议或复测计划；
- 原始答卷和当前结果继续保留。

## 7. 答卷生命周期

```text
NOT_STARTED
    → IN_PROGRESS
    → SUBMITTED
    → CALCULATING
    → CALCULATED
```

规则：

- `IN_PROGRESS`允许修改答案；
- `SUBMITTED`之后禁止学生修改；
- 提交必须校验全部题目；
- 重复提交返回已有结果，保持幂等；
- 评分失败进入`CALCULATION_FAILED`，不能伪造成功结果；
- 已完成结果必须保存`scale_version`和`rule_version`。

## 8. 测评任务和目标学生

### 8.1 任务

测评任务支持：

- 全校；
- 指定年级；
- 指定班级；
- 指定学生。

V1.1采用以下原则：

- 建任务时生成目标学生快照；
- 后续新增学生不会自动改变已发放任务；
- 心理老师可以执行“补发目标学生”；
- 补发行为必须记录审计；
- 完成率按目标行计算，不按当前名册动态计算。

### 8.2 目标行快照

目标行保存当时的：

- 学号；
- 姓名；
- 年级；
- 班级；
- 性别；
- 年龄。

历史任务展示优先使用快照，当前名册仅用于关联当前学生。

## 9. 关怀档案生命周期

```text
PENDING_REVIEW
    → FOLLOWING
    → OBSERVING
    → CLOSED
         ↓
      REOPENED/FOLLOWING
```

状态守卫：

| 当前状态 | 允许操作 |
|---|---|
| 待复核 | 人工复核、跟进、关闭 |
| 跟进中 | 跟进、家庭回访、复测、关闭 |
| 观察中 | 跟进、家庭回访、复测、关闭 |
| 已关闭 | 只允许查看、重新打开 |

关闭必须填写：

- 关闭原因；
- 关闭说明；
- 已检查后续安排确认。

重新打开必须填写：

- 重新打开原因；
- 操作人；
- 时间。

同一学生允许多个历史关闭档案，但同一时刻最多一条未关闭档案。

## 10. 外部测评导入

导入流程固定为：

```text

```

每批导入必须保存：

- 文件名；
- 文件Hash；
- 实际测评日期；
- 导入人；
- 导入时间；
- 总行数；
- 成功、更新、跳过、错误数量；
- 冲突处置方式。

按“学生 + 测评日期所在自然月”判重。覆盖不得删除已经人工复核过的工作记录。

## 16. V1.1.1/V1.2评审修订项

### 16.1 迁移执行边界

`schema_mysql8_incremental_V1.2_完整修订版.sql`是从既有`schema_mysql8.sql`/Alembic历史版本向V1.2过渡的参考增量脚本，不是空库建库脚本，也不建议在生产环境作为一条长SQL直接执行。

正式实现必须拆分为以下迁移步骤，并由Alembic登记版本和校验和：

1. `precheck`：发现重复在办档案、跨学校关系、非法答卷、未知风险类型或规则版本冲突时必须中止；
2. `expand`：只新增表、字段、索引和兼容性约束，不改变既有业务含义；
3. `backfill`：分批回填任务快照、实际测评时间、风险信号和关怀档案关联；
4. `validate`：检查回填数量、跨学生关联、时间有效性和唯一性；
5. `enforce`：在验证通过后启用复合外键、唯一索引和新写入约束；
6. `compatibility cleanup`：确认历史数据已完成过渡后，再把新记录中的关键关联改为非空。

由于MySQL的`ALTER TABLE`可能隐式提交，系统必须准备数据库备份、失败恢复和向前修复方案，不能依赖普通事务回滚整个迁移。

### 16.2 任务范围与目标学生

`assessment_task_scope`保存任务设计时选择的学校、年级、班级或学生范围；`assessment_target`保存实际发放时的学生目标快照。两者不可混用。任务创建后新增的名册学生不会自动进入历史任务，必须通过“补发目标学生”显式加入。

新增或补发目标学生时必须：

- 记录操作者、原因和变更前后数量；
- 不自动把后来新增的学生加入历史任务；
- 保持`assessment_target`唯一；
- 目标快照一经任务开始不得被当前花名册覆盖；补发目标必须标记来源、原因和补发批次。

### 16.3 导出任务

重点学生导出必须创建`export_job`，不得只生成一次性临时下载链接。

导出任务至少保存：

- 操作者、用途、数据范围快照；
- 脱敏级别和字段白名单；
- 生成状态、文件位置、文件过期时间；
- 文件行数、下载时间、下载次数和撤销时间；
- 对应的审计事件。

导出文件默认短期有效，过期后自动失效。导出接口不得接受任意字段名，只能从后端允许的字段白名单中选择。

### 16.4 关怀档案一致性

跟进、家庭回访、复测和生命周期事件同时保存`student_id`与`care_case_id`时，两个字段必须指向同一学生。优先使用复合外键；无法通过历史数据回填的记录进入待人工归档队列。

新建记录的规则：

- `care_case_id`必须非空；
- 关怀档案必须属于当前访问范围；
- 关闭档案不可直接新增跟进，必须先重新打开；
- 关闭、重新打开、转派负责人需要乐观锁或版本号，防止并发覆盖。

### 16.5 认证会话和密码重置

JWT或不透明Token都必须携带可撤销的会话标识，并与`auth_session`关联。每次敏感接口访问都要检查会话是否过期、撤销或被强制下线。

管理员重置密码必须填写原因，重置后：

- 目标账号强制下次登录改密；
- 旧会话全部撤销；
- 不返回或记录明文密码；
- 记录目标账号、操作人、时间、原因和结果。

### 16.6 审计不可抵赖要求

敏感读取、原始答卷查看、重点题查看、家庭回访查看、重点学生导出、账号重置和关怀档案状态变更必须在响应前写入审计。

审计明细只能保存业务元数据和脱敏信息，不得保存原始答卷、重点题答案、家庭回访正文、密码或Token。审计记录原则上只允许追加，不允许普通业务用户修改或删除。

### 16.7 外部导入幂等和来源时间

文件Hash用于识别重复来源，不作为唯一业务结果。重复文件应进入“重复批次”状态并指向原批次，不能因数据库唯一冲突导致用户无法预览。

批次时间和行级时间的优先级固定为：

```text
行级实际测评时间 > 批次默认测评时间 > 待核验
```

导入的本地时间必须携带来源时区，转换为UTC保存。无法确认实际测评时间时，不得使用导入时间冒充测评时间。

### 16.7.1 无学号匹配和年龄变更

无学号时只能在当前学校范围内按标准化姓名、年级和班级匹配；年龄只用于校验或消歧。匹配失败、同名歧义、任务外学生和年龄冲突都必须逐行停留在预览/待处理状态。

外部年龄不一致时，`student.age`与`assessment_session.age_at_test`必须分别保存。覆盖当前名册年龄必须经过确认，并在`student_age_change_log`保留旧值、新值、批次、行号、操作人和原因。

### 16.7.2 在线/外部结果冲突

`assessment_session`允许保留不同来源的多次事实，通过`is_effective`和冲突处置记录保证同一任务学生只有一个有效结果；原始答案、外部汇总结果和人工选择不得相互覆盖。外部汇总结果不得伪造本地100题答案。

### 16.8 答卷哈希和计算幂等

`answer_snapshot_hash`必须使用固定的规范化算法生成：按题号升序拼接量表编码、量表版本、题号和答案，再计算SHA-256，并同时保存算法名称。

评分服务必须支持：

- `PENDING → CALCULATING → CALCULATED`；
- `CALCULATING → CALCULATION_FAILED`；
- 失败重试幂等；
- 同一会话并发计算互斥；
- 不信任前端提交的分值；
- 历史规则不能覆盖已保存结果。

### 16.9 时间、保留和未成年人数据治理

所有时间由应用按UTC写入，数据库连接固定使用UTC，接口返回带时区的ISO 8601时间；学校时区单独配置，仅用于界面展示和本地日期输入。

正式上线前必须确认：

- 测评数据和家庭回访的保存年限；
- 学生毕业、转学后的归档策略；
- 数据匿名化、删除和导出申请流程；
- 备份保留期限和恢复演练频率；
- 导出文件自动过期和撤销机制；
- 隐私告知及必要的授权确认。

### 16.10 评审版尚未关闭的事项

以下内容在业务确认前标记为`TODO_BUSINESS_CONFIRMATION`，Coding AI不得自行定稿：

1. 学校心理数据的法定/校内保存期限；
2. 是否需要学生或监护人隐私告知确认记录；
3. 德育领导可查看的个体摘要字段范围；
4. 紧急访问高敏感数据的“破窗”审批规则；
5. 导出文件的默认有效期和最大行数；
6. 复测建议的默认期限和逾期处理；
7. 外部导入覆盖已人工复核答卷的最终审批人。

## 18. V1.2统一测评任务和外部导入模型

本章统一规定全校名册、测评任务、目标学生、外部导入批次和实际测评结果的关系。

### 18.1 四类核心对象

| 对象 | 业务含义 | 是否等同于一次测评 |
|---|---|---:|
| `assessment_task` | 一次学校组织的测评活动 | 是 |
| `assessment_target` | 本次任务应参加的学生快照 | 否 |
| `assessment_import_batch` | 外部平台一次文件/接口导入 | 否 |
| `assessment_session` | 某学生在某任务下的一次实际答题或导入结果 | 是 |

一个任务可以有多个外部导入批次。面向任务的导入批次必须归属一个学校和一个测评任务；历史外部结果可以暂时不绑定任务，但不得计入任何任务完成率。外部导入批次不得自动创建新的测评任务；如需创建新任务，必须由心理老师明确选择“新建外部测评任务”。

### 18.2 全校名册和任务目标

全校学生名册是基础身份数据，至少保存：

```text
student_no
name
grade
class
age
school_id
```

创建测评任务时，根据学校、年级、班级或指定学生选择目标范围，并生成`assessment_target`快照。快照保存学号、姓名、年级、班级、年龄、目标来源和快照时间。

任务创建后新导入的学生不会自动进入既有任务。只有心理老师执行“补发目标学生”并确认后，才可以新增目标行。补发必须记录原因、操作者、前后人数和审计事件。

如果“学生批次”是学校自定义的一组学生，而不是年级/班级范围，必须先把这组学生固化为指定学生集合，再写入任务目标，不得把外部导入批次直接当成学生目标批次。

### 18.3 外部导入文件要求

外部平台没有学号时，每一行至少需要姓名、年级、班级和年龄；实际测评日期可以按“行级日期优先、批次日期兜底”提供。如果外部文件只有姓名和分数，缺少年级、班级，不能自动匹配，必须进入待人工匹配。

外部导入还必须明确学校、目标测评任务、外部平台名称、外部结果编号（如平台提供）、外部量表版本、外部规则版本，以及是完整100题答案还是汇总结果。

### 18.4 无学号匹配规则

匹配不使用模糊姓名直接认领学生，固定按以下顺序执行：

1. 限定当前学校；
2. 标准化姓名，去除首尾空格和不可见字符；
3. 将外部年级、班级映射为系统标准年级、班级；
4. 按`school_id + grade_id + class_id + normalized_name`查找候选；
5. 年龄用于校验和消歧，不作为唯一身份；
6. 只有唯一候选且没有未处理冲突时，才允许自动匹配。

匹配成功后必须同时保存标准学生ID、学校ID、年级ID和班级ID，不能只保存一组原始文本；原始字段和标准化字段都要保留，便于复核和重放。

匹配状态固定为：

| 状态 | 说明 | 是否写入测评结果 |
|---|---|---:|
| `MATCHED` | 找到唯一学生 | 是 |
| `AGE_CONFLICT` | 学生唯一但年龄不一致 | 人工确认后是 |
| `AMBIGUOUS` | 同名同年级同班存在多个候选 | 人工选择后是 |
| `NOT_FOUND` | 找不到学生 | 否 |
| `OUT_OF_SCOPE` | 学生存在但不属于当前任务 | 否，除非确认补发 |
| `DUPLICATE` | 当前任务已有有效结果 | 否 |
| `INVALID_ROW` | 姓名、年级或班级缺失/非法 | 否 |
| `CONFLICT` | 与在线答卷或其他有效结果冲突 | 人工处置后决定 |

系统不得因为外部结果找不到学生而自动新建学生档案。应先补充学生名册，再重新匹配。

### 18.5 年龄冲突和覆盖

年龄字段分为两个事实：

```text
student.age                    当前学生档案年龄
assessment_session.age_at_test 本次测评时年龄
```

外部年龄与学生档案年龄不一致时，系统必须在导入预览中显示旧值和新值，并提供保留系统年龄、覆盖学生当前年龄、只保存本次测评年龄三个选项。

默认不静默覆盖。确认覆盖后必须保存修改前年龄、修改后年龄、导入批次和行号、操作人和时间、覆盖原因。

无论是否覆盖`student.age`，本次测评的`age_at_test`都必须保存外部测评时年龄。年龄不能参与学生唯一键，也不能因为年龄增长而创建新学生。

### 18.6 分批导入和逐行处理

同一个测评任务可以分多批导入，批次人数可以不同，批次之间可以有重复学生。

导入固定采用：

```text
选择学校和任务 → 上传文件 → 解析 → 逐行匹配
→ 展示成功/冲突/任务外/未找到 → 选择处置策略
→ 确认提交 → 写入有效结果 → 更新目标行和统计
```

每批导入必须保存总行数、成功、更新、跳过、重复、任务外、未匹配、冲突和错误数量。任何未处理的冲突不得进入正式结果。

行级幂等优先使用`source_system + external_result_id`。如果外部平台没有结果编号，才使用“学生 + 实际测评日期 + 量表版本”作为候选判重键，并要求人工确认。

### 18.7 任务外学生

同一学校且属于任务原定范围、但因任务创建后才进入名册的学生，标记`SUPPLEMENT_CANDIDATE`，由心理老师确认补发目标。其他年级、班级或学校的学生标记`OUT_OF_SCOPE`，不计入本任务完成率。

任务外记录可以另存为学生历史外部测评，但不得自动变成本任务结果，也不得自动生成本任务风险事件。

### 18.8 在线测评和外部结果冲突

一个任务一个学生可以保留多个来源事实，但同一时刻只能有一个有效结果。

| 当前状态 | 外部导入行为 |
|---|---|
| 没有在线会话 | 可创建外部测评会话 |
| 在线答题进行中 | 标记冲突，禁止自动覆盖 |
| 在线答卷已提交 | 默认拒绝覆盖，需新建复测/补充任务或人工选择有效结果 |
| 已有外部有效结果 | 相同外部结果幂等；不同结果进入冲突处置 |

冲突处置固定支持`KEEP_ONLINE`、`USE_EXTERNAL`、`REJECT_EXTERNAL`、`KEEP_BOTH_BUT_ONE_EFFECTIVE`。原始在线答卷、外部文件事实和人工选择都必须保留。

### 18.9 外部完整答案和外部汇总结果

如果文件包含100道原始答案，导入后使用本地Scale Engine计算并生成本地结果。

如果文件只有总分和维度分，必须标记为`EXTERNAL_SUMMARY`，不得伪造100道`assessment_answer`，也不得直接按照本地重点题规则生成风险事件。外部结果必须保存外部版本、外部规则、原始分数和核验状态。

### 18.10 任务统计口径

任务统计必须区分目标人数、补发人数、已完成、进行中、未开始、请假/免测、重复导入、任务外学生、未匹配学生和冲突待处理。

有效完成率为：

```text
已完成有效结果 / 应测人数
应测人数 = 任务目标人数 - 请假 - 免测 - 已排除
```

任务外、重复、未匹配和冲突记录不进入任务完成率。

### 18.11 V1.2新增接口

```text
POST /student-roster/import/preview
POST /student-roster/import/commit
GET  /assessment-tasks/{task_id}/targets
POST /assessment-tasks/{task_id}/targets/supplement
POST /assessment-imports/{batch_id}/preview
POST /assessment-imports/{batch_id}/commit
PATCH /assessment-import-rows/{row_id}/resolve
GET  /assessment-tasks/{task_id}/unmatched-import-rows
GET  /assessment-tasks/{task_id}/non-participants/export
```

所有接口必须执行角色权限、数据范围和字段敏感级别校验。

## 19. 与最初版本的主要差异

| 初始版本设计 | V1.2修订结果 |
|---|---|
| 外部导入主要按学号匹配 | 支持无学号，按学校+年级+班级+姓名匹配，年龄用于校验和消歧 |
| 导入结果默认写入会话 | 先逐行预览，区分匹配、任务外、重复、冲突和未找到 |
| 一个任务一个学生一条会话 | 可保留多个来源事实，但只能有一个有效结果 |

| 找不到学生缺少闭环 | 进入未匹配列表，不自动创建学生，可补名册后重试 |
| 导入批次容易与测评任务混淆 | 明确任务、目标、导入批次、会话四层模型 |
| 任务外学生缺少规则 | 不计入任务，或经确认补发为目标学生 |
| 任务完成率较简单 | 排除请假、免测、任务外、重复和冲突记录 |
| 导入规则偏文件级 | 增加逐行状态、逐行处置和逐行审计 |

6. 确认覆盖年龄后保留旧值、新值、操作人、批次和时间；
7. 找不到学生时进入`NOT_FOUND`，不能自动创建学生；

15. 任务完成率只统计有效目标学生和有效结果；
16. 导入、年龄覆盖、补发目标、冲突选择均写入审计。
