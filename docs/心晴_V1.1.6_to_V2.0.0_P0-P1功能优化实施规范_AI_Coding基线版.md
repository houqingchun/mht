# 心晴·中学生心理测评与关怀平台
# V1.1.6 → V2.0.0 P0-P1 功能优化实施规范（AI Coding 基线版）

> 文档用途：AI Coding 实施输入  
> 源码基线：`houqingchun/mht`，分支 `V1.1.6`  
> 目标版本：`V2.0.0`  
> 范围：仅 P0-P1  
> 明确排除：P2、MHT 评分规则修改、既有导入批次体系重构、部署方式重构

---

## 1. 目标

本轮优化目标不是重构现有系统，而是在 V1.1.6 已有稳定能力基础上，补齐正式产品化所需的高优先级能力，重点解决：

1. 测评任务无法删除/作废，导致客户长期使用后任务列表堆积。
2. 错误导入任务即使不再使用，仍可能影响统计、学生当前状态与筛查信号。
3. 心理老师页面存在“全校”字样，但后端实际按授权范围返回数据，存在统计口径误读风险。
4. 心理老师与德育领导共用专业报告页面，角色职责边界不够清晰。
5. 专业报告目前使用浏览器 `localStorage` 保存草稿，不是正式业务数据。
6. 正式报告导出仍采用 `window.print()` / 前端 Blob，不符合现有受控导出体系。
7. 部分界面术语仍偏“风险/预警”表达，学校场景专业性可继续收敛。

# 2. V1.1.6 已确认源码事实

AI Coding 实现必须基于以下事实，不得重复建设已有能力。

## 2.1 测评任务已有两种来源

`assessment_task.source` 已存在：

```text
IN_SYSTEM
IMPORTED
```

含义：

- `IN_SYSTEM`：心理老师人工创建，学生在本系统在线答题。
- `IMPORTED`：学生在外部系统完成测评，结果导入本系统后自动形成/复用分析任务。

不得新增第二套 `source_type` 来表达同一个概念。

## 2.2 外部导入批次体系已存在

V1.1.6 已存在：

```text
assessment_import_batch
assessment_import_row
assessment_external_result
```

现有导入链路已经支持：

```text
上传文件
→ 预览入库
→ 行级匹配/冲突处理
→ commit
→ assessment_session / result
```

同一个外部导入任务下已经可以存在多个 `assessment_import_batch`。

本轮禁止重新建设“导入批次”模型。

## 2.3 外部导入任务已按月复用

V1.1.6 `assessment_import_service._task_for_month()` 已实现：

```text
同一学校 + 同一测评月份 + source=IMPORTED
→ 复用同一个 assessment_task

跨月份
→ 新建新的 IMPORTED task
```

因此当前客户看到很多任务，不应再解释为“V1.1.6 每导入一次就新建一个 task”。

可能来源包括：

- 历史版本遗留任务；
- 不同测评月份；
- 导入时使用了不同测评日期；
- 显式绑定了不同已有任务；
- 人工创建任务本身积累。

## 2.4 当前无任务删除/作废接口

当前任务 API 主要包括：

```http
GET   /assessment-tasks
POST  /assessment-tasks
PATCH /assessment-tasks/{id}
```

当前没有正式：

```http
DELETE /assessment-tasks/{id}
```

也没有完整任务作废治理。

## 2.5 不能只在 UI 隐藏任务

当前学生“最新有效结果”依赖：

```text
assessment_session.is_effective = true
```

全局统计、学生当前状态等会读取有效 session。

因此：

```text
仅把 task 从列表隐藏
```

不会自动让该任务下结果失效。

任务删除/作废必须同时处理数据有效性。

# 4. P0-01 测评任务删除 / 作废治理

## 4.1 业务目标

用户在界面上只需要理解：

```text
删除任务
```

但后端必须区分两种情况：

```text
无正式测评事实
→ 物理删除

已有正式测评事实
→ 业务作废
```

不得将两种语义混为一个无条件 SQL DELETE。

## 4.2 物理删除判定

允许 Hard Delete 的核心原则：

> 当前任务尚未形成不可逆的正式测评事实。

不能简单使用：

```text
target_count == 0
```

作为条件。

原因：人工创建任务时系统会立即生成：

```text
assessment_task_scope
assessment_target
```

即使没有任何学生开始答题，也已经存在目标行。

### 建议 Hard Delete 条件

同时满足：

```text
1. 不存在 assessment_session
2. 不存在 assessment_result
3. 不存在已 COMMITTED 的 assessment_import_batch
4. 不存在已产生的 risk_event
5. 不存在依赖该 task 的已生效正式业务事实
```

此时允许物理删除。

## 4.3 Hard Delete 删除顺序

对于可物理删除任务：

```text
assessment_target
assessment_task_scope
未提交/无正式结果的相关临时数据（仅在明确安全时）
assessment_task
```

必须由服务端事务完成。

禁止：

- 前端直接拼 SQL；
- 依赖数据库级 `ON DELETE CASCADE`；
- 删除任何已提交正式心理事实。

## 4.4 已有正式事实时执行业务作废

建议扩展任务状态：

```text
VOIDED
```

新增字段：

```text
voided_at
voided_by
void_reason
```

建议通过 Alembic 增量迁移新增。

### 任务作废后

```text
assessment_task.status = VOIDED
```

并执行：

```text
该 task 下所有当前有效 assessment_session
is_effective = false
```

目的：确保错误任务不再参与：

- 学生当前状态；
- 最新有效测评结果；
- 聚合统计；
- 当前关注等级判断。

## 4.5 RiskEvent 处理规则

外部导入与在线答题都可能产生 `risk_event`。

任务作废时：

### 尚未处理

```text
risk_event.status = PENDING
```

建议转为：

```text
VOIDED
```

并补充：

```text
void_reason
voided_at
voided_by
```

若本轮不希望修改 `risk_event` 表结构，可至少使用既有可容纳状态的字段，并通过审计保存作废原因。

### 已经人工复核

如果：

```text
risk_event.status != PENDING
```

或者已经有：

```text
manual_review
care_case
follow_up
family_contact
retest_plan
```

则：

```text
不得删除
不得覆盖
不得自动回滚人工记录
```

历史专业工作必须保留。

## 4.6 关怀档案处理原则

明确：

```text
删除/作废测评任务
≠
删除关怀档案
```

已经发生的：

- 人工复核；
- 跟进；
- 家庭回访；
- 复测；
- 档案关闭/重开；

均属于独立专业工作事实。

任务作废后：

- 保留全部历史记录；
- 可在相关历史页面增加“来源测评任务已作废”提示；
- 不允许自动删除或修改心理老师已确认的专业事实。

## 4.7 删除影响预览 API

新增：

```http
GET /api/v1/assessment-tasks/{task_id}/delete-check
```

建议响应：

```json
{
  "taskId": 123,
  "taskNo": "IMPORT-202609-1",
  "source": "IMPORTED",
  "status": "CLOSED",
  "deleteMode": "VOID",
  "canHardDelete": false,
  "targetCount": 980,
  "sessionCount": 976,
  "resultCount": 976,
  "importBatchCount": 3,
  "committedImportBatchCount": 3,
  "riskEventCount": 21,
  "pendingRiskEventCount": 6,
  "manualReviewCount": 3,
  "careCaseCount": 5,
  "warning": "该任务已产生正式测评结果，删除将按作废处理，原始历史与人工关怀记录会保留。"
}
```

### deleteMode

```text
HARD_DELETE
VOID
```

## 4.8 删除 / 作废 API

建议统一用户动作：

```http
DELETE /api/v1/assessment-tasks/{task_id}
```

请求体：

```json
{
  "reason": "导入文件错误，重新导入后不再使用"
}
```

服务端根据 delete-check 判定：

```text
HARD_DELETE
或
VOID
```

响应：

```json
{
  "taskId": 123,
  "mode": "VOID",
  "status": "VOIDED"
}
```

如项目现有 HTTP 客户端不适合 DELETE body，可采用：

```http
POST /api/v1/assessment-tasks/{task_id}/delete
```

AI Coding 应遵循项目现有 REST 风格选定一种，不得同时实现两套语义重复接口。

## 4.9 权限

默认建议：

| 角色 | 删除无事实任务 | 作废已有事实任务 |
|---|---:|---:|
| 心理老师 | 是（需在数据范围/任务权限内） | 是 |
| 德育领导 | 否 | 否 |
| 系统管理员 | 否（默认） | 否（默认） |
| 学生 | 否 | 否 |

原因：当前测评任务写权限归心理老师。

不得因为“系统管理员”具有系统管理职责，就让其自动获得心理业务事实删除权限。

如客户未来要求管理员具备运维纠错能力，应单独扩展 Capability，不在本轮隐式放开。

## 4.10 审计

无论 Hard Delete 还是 VOID，都必须写审计。

至少记录：

```text
操作人
操作时间
task_id
task_no
task_name
task_source
删除模式 HARD_DELETE / VOID
删除原因
影响目标学生数
session 数
result 数
导入批次数
risk_event 数
人工关怀是否已产生
```

## 4.11 列表行为

默认任务列表：

```text
不显示 VOIDED
```

增加筛选：

```text
全部
进行中
已结束
已作废
```

只有显式选择“已作废”时显示 VOIDED。

任务卡片/表格中保留：

```text
来源：
在线测评 / 外部导入
```

不得移除 `source` 展示。

## 4.12 统计、报表与下拉必须同步过滤 VOIDED

以下入口必须默认排除：

```text
assessment_task.status == VOIDED
```

包括但不限于：

- 测评任务列表；
- 统计分析任务筛选器；
- 专业报告任务筛选器；
- 导入页面“关联已有任务”下拉；
- 工作台任务统计；
- 领导端任务统计；
- 任务完成率相关聚合。

## 4.13 工作台完成率修正

当前 `counselor_workbench()` 直接统计 `AssessmentTarget`。

新增 VOIDED 后必须：

```text
AssessmentTarget
JOIN AssessmentTask
WHERE AssessmentTask.status != VOIDED
```

否则作废任务仍会影响：

```text
完成率
目标人数
已完成人数
```

## 4.14 最新有效结果口径

除作废操作时将相关 session：

```text
is_effective = false
```

外，建议关键查询增加防御性约束：

```text
task.status != VOIDED
```

尤其：

```text
latest_result_subquery()
latest_session()
学生当前状态
统计分析
```

目的：双重保障。

不得只依赖“作废时正确更新所有 session”这一条路径。

## 4.15 学生历史展示

建议：

学生本人：

```text
默认不显示 VOIDED 任务对应记录
```

心理老师专业档案：

可保留：

```text
显示已作废记录
```

但明确标识：

```text
已作废，不参与当前判断
```

## 4.16 外部导入任务特别规则

已有 `assessment_import_batch` 必须保留。

当 IMPORTED task 被 VOID：

```text
assessment_import_batch
assessment_import_row
assessment_external_result
```

不得物理删除。

原因：它们是导入来源与审计事实。

仅改变：

```text
任务有效状态
对应 session 有效状态
未处理 risk_event 状态
```

## 4.17 历史旧任务清理

由于旧版本可能存在：

```text
同月多个 IMPORTED task
```

本轮允许用户逐条作废。

禁止 AI Coding 自动合并历史 task。

禁止后台自动判断“这是重复任务”后批量删除。

未来如需要历史治理工具，另立需求。

# 5. P0-02 数据范围显性化

## 5.1 问题

V1.1.6 后端统计已经按：

```text
student_scope_predicate()
```

执行数据范围过滤。

但前端部分心理老师统计页面仍使用：

```text
全校预警总览
全校八维度分析
```

这会造成：

```text
页面文字：全校
实际数据：授权年级 / 班级
```

属于统计口径误导。

## 5.2 目标

所有心理老师统计页面必须明确展示：

```text
当前数据范围
```

例如：

```text
当前数据范围：初一年级
```

或：

```text
当前数据范围：初一 1 班、初一 2 班
```

德育领导 SCHOOL 范围：

```text
当前数据范围：全校
```

## 5.3 数据范围摘要接口

优先复用现有 `/me` 已有信息。

若现有返回不足以生成稳定展示文本，则新增：

```http
GET /api/v1/me/data-scope-summary
```

响应：

```json
{
  "scopeType": "GRADE",
  "displayText": "初一年级",
  "schoolWide": false
}
```

不得让前端根据零散字段自行猜测范围。

## 5.4 页面标题修订

心理老师：

```text
全校预警总览
→
筛查关注概览
```

```text
全校八维度分析
→
八维度分析
```

页面内通过：

```text
当前数据范围
```

表达真实范围。

德育领导可以保留“全校”含义，但建议统一页面组件标题，范围通过 scope badge 表达，避免一套组件出现两套硬编码标题。

## 5.5 验收

必须验证：

1. SCHOOL counselor → 显示全校。
2. GRADE counselor → 显示指定年级。
3. CLASS counselor → 显示指定班级。
4. Leader → 显示全校。
5. 不允许“页面显示全校、数据实际 scoped”。

# 8. P1-03 专业报告接入现有 Export Job

## 8.1 当前问题

V1.1.6 正式报告页面仍采用：

```text
window.print()
前端 Blob HTML
```

系统本身已经存在：

```text
export_job
```

# 15. Definition of Done

本轮完成必须同时满足：

## Task Governance

- 心理老师可以删除误创建且无人参与的任务。
- 有正式测评结果的任务不会物理删除。
- 有正式事实的任务可作废。
- 作废 session 不再作为当前有效结果。
- 作废任务不再影响当前统计。
- 作废任务默认不出现在任务列表、统计任务选择、报告筛选。
- 外部导入 batch 不因任务作废而删除。
- 人工关怀历史不因任务作废而删除。
- 删除/作废全量审计。

## Scope

- 心理老师所有统计页面显示当前授权数据范围。
- 页面不再出现“显示全校但实际只统计年级/班级”的情况。

## Professional Report

- counselor 与 leader 页面职责分离。
- 专业报告正式服务端保存。
- 报告支持版本。
- 历史报告统计快照不漂移。
- leader 只读。
- admin 默认不可读取专业正文。

## Export

- 正式报告通过现有 Export Job。
- 正式导出不再依赖浏览器 Blob / window.print。
- 导出可审计。

## Vocabulary

- 学生端/领导端避免标签化语言。
- 统计与报告主要使用“关注/筛查”体系表达。
