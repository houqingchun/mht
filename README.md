# 心晴中学生心理测评与关怀平台

本项目按 `vibe-input` 规格分阶段开发。当前已完成 Phase 0-8 全部功能。

## 技术栈

- 前端：Vue 3 + TypeScript + Vite
- 后端：Python + FastAPI + SQLAlchemy + Alembic
- 数据库：MySQL 8.0
- E2E 测试：Playwright
- 部署：两条路，各有各的场景
  - **Windows 一键安装包**（推荐给学校那台机器）——一个 zip，解压、双击、后台常驻、开机自启。**不需要 Docker。** 见下
  - **Docker Compose**（mysql + backend + frontend）——见下

## 快速开始

```bash

# 启动开发服务器（后端 + 前端）

# 或分别启动
make backend   # http://127.0.0.1:8000
make frontend  # http://localhost:5173
```

#### 清库到「只有管理员 + 基本配置」

交付/换环境时，把上面 `make seed` / `make seed-demo` 填进去的一切清掉，只留 `admin`
与机构配置：

```bash
python -m app.db.seed                                   # 先把基线写好（或库里已经有）
mysql -h 127.0.0.1 -u root -p xinliceping < sql/reset_to_baseline.sql
```

清完剩下：`school` 1 行、`system_setting`、`role_permission`、已发布的量表（含 100 道题与
它的评分规则）、`user_account` 只有 `admin`、以及它的 `user_scope` 行。名册、员工账号、
测评任务与一切测评/关怀记录全清。

这个脚本**只删行，不建表也不建行**：表结构归 `alembic upgrade head`，基线数据归
`python -m app.db.seed`。所以它需要在一个已经迁移过、且已经有 `admin` 的库上跑——
脚本找不到 `admin` 时会明确告诉你，并且**一条都不删**。整个过程是一个事务，
别加 `mysql --force`（那会跳过错误继续跑）。可重复执行。

`make purge-demo` 是另一件事：它只把 `seed-demo` 填的东西删掉，回到 `seed.py` 的基线
（S001、两名种子员工、基线任务都还在），而且只在开发库上用。

#### `backend/sql/` 下另外三份脚本（面向交付，不是给开发库用的）

| 文件 | 做什么 | 谁用 |
|---|---|---|
| `schema_mysql8.sql` | 建 34 张表 | 目标机跑不了 Python、只能手工建表时 |
| `upgrade_from_v1_0_0.sql` | 把停在 V1.0.0 的库升到当前版本 | 同上，且库是旧版 |
| `seed_mysql8.sql` | 空库的初始化数据：量表 + 100 道题 + 评分规则 + `admin`（初始密码 `123456`），**不含任何演示数据** | 自己建了空库的人——没有数据就登录不进去 |

三份都随一键安装包一起交付。后两份是**生成的**（`make db-upgrade-sql` /
`make db-seed-sql`），别手改，改了下次重跑就没了；`seed_mysql8.sql` 生成时要连上一台
活着的 MySQL（它 dump 的是 `seed.py` 跑完再清库之后的**结果**）。四份脚本各自的分工与
执行方式见 `deploy/README.md`。

## 部署到 Windows（一键安装包）

给**装不了 Docker** 的学校服务器（Windows + 已装 Python 3.11 + MySQL 8.0 Server），
**安装的人不需要是技术人员**。

### 出一份包（在开发机上）

```bash
make deploy-package     # -> dist/心晴部署包_V<版本>.zip，约 11MB
```

包里带着 Windows 版的依赖 wheel 与已经构建好的前端，**运行环境是安装时用目标机上那个
Python 3.11 现建的 venv**（2026-09-18 起不再内嵌 CPython，zip 从 22MB 降到 11MB），
所以目标机上不需要 pip、不需要网络——要有的外部东西是 **Python 3.11 x64** 与 MySQL 8.0。
自检会在出包时逐个核对必需文件、依赖闭环、编码约定与中文文件名。

### 在目标机上装

1. 把 `心晴部署包_V<版本>.zip` 拷过去
2. **解压**
3. 双击 `一键安装.bat`（会弹一次 UAC）

然后回答一屏问题：装到哪、用哪个端口（默认 **8000**）、MySQL 怎么连、**管理员密码**。
结束时会打印老师该访问的地址（`http://<本机局域网IP>:8000/`）。

装完之后：

- 服务由一条**「计算机启动时」触发的计划任务**跑着（以 SYSTEM 身份），
  **重启后不需要有人登录就自己回来**；崩溃与数据库未就绪由 `run_server.py` 自己重试。
- 安装目录里多出八个中文按钮：`启动服务 / 停止服务 / 重启服务 / 查看状态 / 查看日志 /
  备份数据 / 重置管理员密码 / 卸载`。**「查看状态」是排查问题的入口**，它会打印
  服务在不在、老师该访问哪个地址、日志占多大。
- **重跑一次 `一键安装.bat` 就是升级**：不再问数据库、不重建库，只覆盖程序文件并跑一次迁移。

包根那份 `部署说明.txt` 是写给操作员的（三步操作、装完的自检清单、
「网页打不开」的分诊表、被杀毒软件拦住了怎么办）。面向维护者的在 `deploy/README.md`。

> **这套部署没有做**：TLS（只给局域网用）、多校、备份自动上传。
> 备份要人定期把 `backups\` 里的 `.sql` 拷走——脚本只在本机落一份。

### 前端必须同源

前端 `services/api.ts` 的 `API_BASE = '/api/v1'` 是**相对路径**，`createWebHistory()`
没带 base，所以生产环境要么后端一个端口同时发 API 与页面（一键安装包走这条，
靠 `XLP_WEB_DIR`），要么中间放个 nginx（`frontend/nginx.conf`，Docker 走那条）。**没有第三种。**

### 环境变量（`XLP_*`）

后端配置全部走 `XLP_` 前缀，读的是**当前工作目录**下的 `.env`（缺失时静默跳过，
所以生产启动器 `backend/run_server.py` 会先 `chdir` 到仓库根）。

| 变量 | 默认 | 说明 |
|---|---|---|
| `XLP_DATABASE_URL` | `mysql+pymysql://root:password@127.0.0.1:3306/xinliceping` | 口令里的 `@ : / #` 必须百分号编码 |
| `XLP_HOST` | `127.0.0.1` | 一键安装包写 `0.0.0.0`（老师要从别的机器访问） |
| `XLP_PORT` | `8000` | 安装时可改 |
| `XLP_WEB_DIR` | *(空)* | 前端构建产物的目录。**空 = 不托管前端**，开发与 e2e 因此一字不变 |
| `XLP_LOG_DIR` | *(空)* | 空 = 只往 stdout 打；生产写 `<安装目录>/runtime/logs` |
| `XLP_LOG_LEVEL` | `INFO` | |
| `XLP_DOCS_ENABLED` | `1`(开) | `/docs`、`/redoc`、`/openapi.json`。**生产安装脚本写 `0`**：那一整个网段的人都能拉到整套接口形状 |
| `XLP_JWT_SECRET` | `dev-only-change-me-dev-only-change-me` | **生产必须换**（安装脚本每次随机生成一个） |
| `XLP_JWT_ALGORITHM` | `HS256` | |
| `XLP_ACCESS_TOKEN_EXPIRE_MINUTES` | `120` | 登录凭据有效期 |
| `XLP_PASSWORD_LOCK_THRESHOLD` | `5` | 连续失败几次锁定 |
| `XLP_PASSWORD_LOCK_MINUTES` | `30` | 锁多久 |
| `XLP_API_PREFIX` | `/api/v1` | |
| `XLP_APP_NAME` | `心晴心理测评与关怀平台` | |

**CORS 源不在环境变量里**：`app/main.py` 硬编码了开发用的两个 `localhost:5173` 源
（同源部署用不到它们，所以一键安装包不需要配）。

Docker 那条路的环境变量在 `docker-compose.yml` 里，同一套名字。

## 导入与发布：权限划分

**权限按风险性质划分，而不是按"谁在用"：**

| 动作 | 风险性质 | 归属 |
|---|---|---|
| 学生信息导入 | 账号与组织治理（创建登录凭据、组织结构） | **系统管理员** |
| 员工账号的建立 / 改范围 / 停用 | 账号与组织治理（同上；且建号时就要定下这个人能看哪些学生） | **系统管理员** |
| MHT 题库导入（产草稿） | 低 —— 草稿不生效，不改变任何判定 | **系统管理员 + 心理老师** |
| MHT 测评记录导入（外部平台结果） | 中 —— 写的是测评事实，判定口径与系统内作答一致（会开出风险提示与关怀档案），但不建账号、不动组织结构 | **系统管理员 + 心理老师** |
| **题库发布**（草稿 → 生效） | **高** —— 改变全校后续测评的判定依据 | **系统管理员** |
| 修改评分规则 | 高 —— 同上 | **系统管理员** |

关键区分是**草稿不生效**：

- 导入只创建 `status="DRAFT"` 的版本，不参与任何评分，新建任务也不会选中它；
- 只有 `POST /scales/versions/{id}/publish` 把它变成 `PUBLISHED`，同时把同量器的上一个已发布版本转为 `ARCHIVED`（保留，不删除，历史结果仍可追溯）；
- 发布与改规则都写审计。

### 学生信息导入的列格式

模板在「组织学生 → 学生导入 → 下载模板」取得。**服务端没有模板端点**（V1.2 阶段 3 删掉了
`GET /students/import/template`：它没有调用方也没有测试，前端那份就是唯一的一份）：


```
学号,姓名,年级,班级,性别,年龄
27025160101,示例学生,初一,701,男,12
27025160102,示例学生,初二,801,女,13
```

- **班级按学校编号填**：`701` = 初一 1 班，首位 `7 / 8 / 9` 分别是初一 / 初二 / 初三；
- **年级与班级首位数字必须一致**，对不上按行报错（`班级 701 属于初一，与年级 初二 不一致`）。年级只认 `初一 / 初二 / 初三` 三个名字，写「七年级」会被挡下来——否则系统会悄悄新建一个年级；
- 年级、班级、学号、姓名必填；**性别与年龄选填**，性别可填 `MALE/FEMALE` 或 `男/女`，年龄填 `13`（也认 `13岁`）；
- **最后一列是年龄，不是出生日期。** 名册上只有年龄这一个数，所以 2026-09-17 起库里的 `student.birth_date` 换成了 `student.age`（迁移 `0011_student_age`）。**年龄存下来就不再变**，下一年请重新导一次名册。老模板（末列还叫「出生日期」）会被逐行挡下来并提示列已改名，而不是静默导成一册年龄全空的学生；
- 学号不校验格式（各位数字的含义未确认），只校验必填与不重复；**登录账号就是学号**，初始密码 `123456`，首次登录强制改密；
- 表头中英文都认（`student_no` 与 `学号` 等价），CSV 与 JSON 都支持。文件先预览、逐行报错，确认后才写入。
- **「学号已在名册上」要你来拍板，不算错误。** 这类行本身没有填坏——它是与库里已有的数据撞上了，所以预览把它单列成**「待确认」**（与 MHT 记录导入同一形状），并给出两条路：
  - **覆盖**：用这份文件里的信息更新那几名学生——只换**姓名、年级、班级、性别、年龄**，外加账号上的显示名。**不删除、不重建**：学生的 `id` 不动，关怀记录、测评历史、风险事件、账号与范围都保留（库里没有级联删除，删一次就是把这些全部悬空）。学号本身不改，**文件里空着的性别 / 年龄保持原样**，不会被清空；
  - **放弃**：这几名学生这次不动，其余记录照常导入。
  选之前「确认导入」是灰的；后端也会在**任何写入之前**拒绝一次未选择处置方式的提交，不会留下半批数据。
  **同一份文件里两行写了同一个学号，仍然是错误**（不是冲突）：那没有「覆盖」可言，是文件坏了。
  入口只有一个：**导航上的「组织学生」**（`/admin/organization`，管理员）。
  「数据中心」是心理老师的页面，管理员打不开它，所以它那里曾经的那份副本恒不可达，
  2026-09-17 已删除。

> 此前 `PUBLISHED` 只由 `seed.py` 写过一次，**没有任何发布接口** —— 导入的题库永远无法被任务使用，界面提示"尚未发布"却无处可发布。现已补齐。

### MHT 测评记录导入的列格式（外部平台已在别处做完的普查）

学校在**其他平台**做完心理普查、想把结果并进本系统一起分析时走这个入口（数据中心 → MHT测评记录导入）。
模板在同一个卡片里下载（`GET /assessment-import/template` 是同一份内容）：

```
姓名,性别,年龄,年级,班级,所用时间,1.题干,…,100.题干
示例学生,2,12,1,4,3600秒,0,…
```

- **只收 `.csv`**。外部平台导出的原始文件（`.xlsx`）请先**另存为 CSV** 再上传——扩展名不对会整份拒掉并提示怎么办；直接喂 xlsx 会读成一行乱码，然后每一行报「缺少姓名」，那比一句话难懂得多。UTF-8（带不带 BOM）与 GBK 都认：中文 Excel / WPS 的「另存为 CSV」在 Windows 上写的就是 GBK。
- **取值是那个外部平台的约定**，本系统别处不出现这两种写法：**性别 `2` = 男、`1` = 女**（也认 `男/女`）；答案 `1` = 是、`0` = 否。
- **年级与班级同样是编号**：年级 `1/2/3` = 初一/初二/初三（也认 `7/8/9` 与中文全名），班级 `4` = 初一 4 班 —— 即「年级前缀 + 班号补两位」→ `704`。这与「学生信息导入」要求的 `701` 是同一套编号。
- **按「姓名 + 性别 + 年龄 + 年级 + 班级」五列一起定位学生**，定位不到就**跳过并逐行报错**，不改名册、不建账号：
  - 名册里没有这个班级 → `名册中没有「初一 704」这个班级`（**先报班级再报人**——合成一句会在班级根本不叫 `704` 时给出假诊断）
  - 班级在、人不在 → `「初一 704」没有叫「张三」的学生`
  - 同班同名 → 先用性别、再用年龄（先精确、后 ±1 岁）消歧，仍不唯一才报错
  - **不在你数据范围内的学生，与「没有这个学生」返回逐字相同的一句话**，否则上传一份文件就能把全校名册枚举出来
- **性别与年龄只用于消歧**（不拿它们写名册上的性别），**但这两列与名册不一致时不是「提示一下就过」**：
  - 性别不符仍只是一句提示，记录照常导入；
  - **年龄不符是一条「待确认」**——你需要选「覆盖」还是「放弃」（见下）。
  作答用时认 `5340` / `5340秒`，认不出就留空（数值列留空是既有约定，不写 0）。表头里的题号必须完整覆盖 1–100 且不重复，否则整份文件报列级错误、不发预览令牌。
- 导入前要填**「批次名称」**（选文件后默认取文件名，可改）与**「测评日期」**（默认今天，不得晚于今天）：文件里只有「哪一天」这一格信息，批次名与日期由人确认，两者都会写进审计。
- **判重按「月」为单位**：同一个学生、同一个自然月里只能有一次外部导入；不同月份是两场不同的测评，会各自建一个批次任务。所以一次普查分两批导（先初一、隔几天再初二）会归到**同一场**任务下，各自的目标行照旧一人一条。**同一月里已经有多个历史批次时，复用最新那一批**，这样提示里的批次号、审计里的对象与你刚改写过的那场会话指的是同一条任务。
- 确认导入会建一个**批次任务**（`IMPORT-YYYYMM-n`，任务名即批次名称），每场会话标为 `IMPORTED`：任务列表、学生档案（「来源」行）与受控导出的「来源」列都会显示**外部导入**。
- **「待确认」需要在导入前拍板**。预览会把两类记录单独列出来——**年龄与名册不符**、**本月已有一次导入**——它们本身没有错，问题是与库里已有的数据对不上，所以要由你回答：
  - **覆盖**：重复的那一场**就地改写**（答卷、结果、八维度按这份文件重算，不新建第二条记录），年龄按文件里的数更新名册（会写一条审计）。上一次那场开出来、**还没人复核过**的风险提示会被收回；心理老师已经复核过的那条留着。
  - **放弃这几条**：只导入其余记录，库里已有的记录与名册都不动。
  选之前「确认导入」是灰的；一条都不导入时不会留下空批次任务。
- **判定口径与学生在系统内作答完全一致**：命中重点题（85 / 97 任一答「是」）同样会开出风险提示与关怀档案，进关怀队列与工作台待办。学生进不了这个答题会话（`SESSION_LOCKED`），学生端看到的是「外部导入 · 已完成」的只读记录。
- ⚠️ **它会改变全校统计**：完成率按任务算、关注率与高度关注导出取**每个学生最新一场**会话（导入的那场若更新，等级就来自外部平台——导出的「来源」列写的正是这个）、德育领导进展同受此影响。这正是把校外结果并进来看的目的，但导入前应当知道。

#### 导入之后，在哪里查某个学生的记录

**「重点学生 → 全部学生」**（心理老师）。这一页是**整份名册**，每人一行取他最近一场测评，列出学号 / 姓名 / 年级 / 班级 / 关注等级 / 总分 / 最近测评 / 来源 / 档案阶段：

- **没有开档案的学生也在**——导入进来、判定为「一般观察」的学生不会开关怀档案，而个案详情、重点学生队列、工作台都以档案为入口，所以他们在那三页上是找不到的。要找刚导进来的人，就来这一页。
- **从没测评过的学生同样列出**，那一格显示「未测评」而不是被丢掉；「只看已测评」开关可以把他们摘出去。
- 支持按姓名 / 学号 / 年级 / 班级搜索，以及年级、班级两个下拉筛选。
- 只有**已建档**的行才给「查看档案」按钮：没有档案的行点进详情是 404，所以按钮不渲染。

**「测评任务 → 查看明细」**（心理老师 / 德育领导）。导入产生的批次任务（`IMPORT-YYYYMM-n`）在列表上显示「已结束」（目标行全部完成）。点开明细能看到**这一批**每个人的状态、关注等级、总分与用时——与上面那个页签的口径不同：**这一页是按场次的**，同一名学生落在两个批次里时两边各自显示各自的分。

> 权限：`GET /students/results` 这一个端点同时要「学生心理详情 = 全量档案访问」与「组织与账号 = 查看必要信息 / 管理」两项能力——响应里既有身份列也有等级列。因此**德育领导与系统管理员都拿不到它**，这是有意的（心理详情不得成为读组织名册的旁路）。详见 CLAUDE.md §4。

## 系统配置

系统管理员可在「系统配置」中调整以下业务配置，修改即时生效并写入审计日志：

| 分组 | 内容 |
|---|---|
| 机构标识 | 学校名称、平台名称与副标题、心理辅导室位置、开放时间、校内联系方式 |
| 关怀词表 | 跟进类型、回访方式、联系结果、家庭支持情况、关闭原因、复测原因、复核结果与下一步安排 |
| 导出与敏感查看 | 受控导出用途、重点题二次查看原因 |
| 跟进节奏 | 新建记录时下次跟进 / 回访 / 复测的默认间隔，及新建任务的默认时长 |
| 界面阈值 | 完成率告警阈值、维度高亮阈值、每题预计耗时 |

实现要点：

- 配置存储在 `system_setting` 表，**按 (namespace, key) 逐项保存**，便于审计精确记录改了什么；写入时若值等于默认值则删除该行，表里只保留偏离项。
- **表为空或读取失败时回退到 `app/services/settings_service.py` 的 `DEFAULTS`**，绝不 fail-open 成"没有任何配置"而把界面清空。
- 只接受 `DEFAULTS` 中声明过的 namespace 与 key，表不会积累无人读取的垃圾。
- **读取对所有已登录用户开放，写入限于「组织与账号 / 管理」能力**。读取若也按能力限制，心理老师、学生、德育领导都会静默回退到硬编码字面量，配置对他们等于失效。
- 登录页需要在校验身份之前显示校名，因此单独提供无需认证的 `GET /public/branding`，仅暴露三个展示字段。
- **改「学校名称」会立刻出现在所有显示校名的地方**，包括新建账号时的「数据范围」下拉框与账号列表的范围列——它们读的是这里的配置，不是组织表里 `school` 那一行的 `name`（那一行由种子与学生导入维护，界面上不显示、也不编辑）。

> 评分阈值**不在**这里，属于量表规则版本（见下节）。

## 量表评分规则

评分阈值（总分分段、维度分段、效度重测阈值）在「量表题库」页随版本一起编辑，**不在系统配置里**。

原因是它们的性质不同：阈值决定「哪些学生被标记为重点关注」，而 `assessment_result.rule_version` 记录每条结果是用哪套规则算出来的。放进通用配置表会让一次误改**追溯改写所有历史结果的解释**，且无法回答"这条结果当时按什么标准判定"。

工作方式：

- 引擎在评分时读取该版本的 `scale_rule.config_json`。此前这份配置**只写不读**，阈值硬编码在 `scale_engine/engine.py` 里，界面改了没有任何效果。
- 保存已发布版本的规则会**生成新的规则版本**（`MHT-RULE-1.1.0` → `1.1.1`），旧版本标记为 `RETIRED` 保留；已有测评结果仍指向原规则版本，不受影响。
- 草稿版本的规则就地修改，因为还没有任何结果用它算过。
- 提供「恢复默认规则」，同样通过新建版本实现，不删除历史规则。
- 保存前校验分段必须连续、无重叠、无断档，且效度题/重点题必须在量表实际题号范围内。

## 角色权限矩阵

系统管理员可在「账号与权限 → 配置权限」中调整五类能力（聚合统计 / 学生心理详情 / 重点题·原始答卷 / 组织与账号 / 受控导出）在四类角色上的授权范围。

- 矩阵存储在 `role_permission` 表；**表为空时回退到 `app/security/permissions.py` 的 `CAPABILITY_DEFAULTS`**，其取值与改造前的硬编码规则逐条一致，因此默认行为不变。
- 查询失败或缺少记录时一律回退默认值，不会「放开为全部允许」。
- **能力的描述性等级不可互换**：`学生心理详情` 的「全量档案访问」与「仅汇总」不是同一个等级——暴露个体明细的端点显式只接受前者，德育领导的「仅汇总」不会被静默提升。受控导出解除姓名遮蔽、以及「全部学生」测评结果列表（它同时带身份列与等级列）都要求「全量档案访问」。
- 系统管理员不能移除自身的「组织与账号」权限，否则将无法再进入权限配置。
- 每次修改写入审计日志。

## 列表排序与分页

所有列表支持点击表头排序（升/降序切换）与分页。审计日志数据量会持续增长，采用**服务端分页与筛选**（`limit` / `offset` / `sort` / `order` / `q` / `actor_role`），返回的 `total` 描述的是**筛选后**的集合——筛选在分页之前生效，因此翻页结果始终一致；其余列表数据量有界，采用客户端排序分页。

维度得分以「得分 / 该维度题数」显示 —— 八个维度题数并不相同（学习焦虑与身体症状各 15 题，其余六个各 10 题），单看数字无法判断强度。接口返回 `max_score` 作为分母。

## 界面上的几条约定

这些是**用户看得见的行为**，改动界面时不要破坏（判定依据与测试见 CLAUDE.md §13–§15）：

- **截断会自己说出来。** 有上限的地方都有一句「还有多少没显示」并指出出路：工作台提醒「另有 N 项未显示」、工作台队列「另有 N 份一般观察档案」、题库导入预览「仅显示前 20 题」、学生导入预览「仅显示前 20 行」、任务完成明细「仅显示前 200 条」。静默丢数据与「这里就只有这么多」在屏幕上长得一模一样。
- **空态与读取失败不是一回事。** 「暂无完成明细」是一句关于数据的断言，只在确实没有数据时出现；读失败会换成一条带「重试」的错误。同一处也不会同时出现「正在加载」和「加载失败」。
- **人数按人去重。** 「导出 N 人」数的是学生，不是档案行数——一名学生可以同时有已关闭的旧档案与在办的新档案。
- **一次失败的读取不留上一次的答案。** 切换版本 / 学生 / 文件之后，界面上不会残留上一个对象的标题、预览或提交令牌。
- **无障碍**：弹窗打开时 Tab 被收在弹窗内、关闭后焦点回到原处；可排序表头键盘可达（Enter / Space），不可排序的表头不带 `aria-sort`；全站有 `:focus-visible` 焦点环；提示消息挂在活动区域上，读屏软件会播报；浏览器标签页标题随页面变化。
- **学生答题页**：题数来自当前这一版题库，不写死 100；**题干拉不到就没有答题页**（宁可重试，也不让学生在不知道题目在问什么的情况下作答）；「上次答到第几题」按会话记在本地，答案一律以服务端为准，共用电脑上不会读到上一个人的进度。

## MHT 量表规则

- 100 题，答案 `YES=1` / `NO=0`
- 效度题：82/84/86/88/90/92/94/96/98/100（排除在内容总分外）
- 重点题：85/97（任一 YES 触发人工复核）
- 总分：1-55 一般范围，56-64 需要关注，65+ 重点关注
- 维度分：0-3 LOW，4-7 MEDIUM，8+ HIGH
- 八个维度以英文编码标识（`LEARNING_ANXIETY`、`INTERPERSONAL_ANXIETY`、`LONELINESS`、`SELF_BLAME`、`SENSITIVITY`、`PHYSICAL_SYMPTOMS`、`PHOBIC_TENDENCY`、`IMPULSIVE_TENDENCY`），中文名由前端 `services/labels.ts` 映射。**注意：不是 A–H 单字母编码。**
